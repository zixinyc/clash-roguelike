# 《余烬交锋》好友 PvP 双开指南

## 极简方案

双方使用同一套固定配置，每人控制灰烬和长锋，携带六张通用牌。各自在自己的窗口选牌、选目标、安排或撤销，按「锁定行动」才发送计划。房主用本地战斗规则核对牌、行动格、目标和 Cost。只有两人都锁定，房主才掷币并结算一遍，把同一场交锋的数据分别转换成双方的视角。等两个窗口播完，房主开启下一回合。

- 规划阶段公开双方队员、速度、行动格和锁定状态。对方的具体卡牌和目标箭头在揭晓前隐藏。
- 拼点优先配对互相瞄准的行动。单向瞄准时，发起瞄准的一方速度更快才可接成拼点。剩余行动按速度分别结算。双方使用相同的正面概率。
- 首版经过两人手动锁定来推进。房间结束或有人断开后，可以回大厅重新建房和加入。

## 本机开两个窗口

从项目根目录 `D:\游戏项目` 打开两个 PowerShell 标签页，在两个标签页分别运行同一条命令。也可以在 Godot 4.7.2 中运行项目，再用 PowerShell 启动第二个实例。

```powershell
& '.\.tools\godot-4.7.2\Godot_v4.7.2-stable_win64_console.exe' --path '.\battle-demo'
```

1. 两个窗口都在阵容配置页点击 **好友对战**。
2. 在窗口 A 点击 **建房**，看到「等待对手」后切到窗口 B。窗口 B 保持 IP `127.0.0.1`、端口 `7000`，点击 **加入**。两边都应进入第一回合。
3. **验证安排和撤销。** A 选「断轨」，B 选「定锋」。双方都把牌安排给左边的灰烬，再把目标选为右边灰烬的「攻」格。用「安排 →」和「撤销此格」各操作一次。两边各自只能看到自己的牌、箭头和预留 Cost。撤销后己方预留 Cost 应恢复，对方仍显示「计划隐藏」。
4. **验证锁定。** 将牌重新安排后，先让 A 按「锁定行动」。B 应看到对手已锁定，具体牌和箭头仍隐藏，战斗应继续等待。再点 B 的「锁定行动」，双方才看到第一回合的技能和拼点演出。
5. **验证回合和结果。** 比较 A 的我方生命、Cost 与 B 的对方生命、Cost，再反过来比较。两边视角相反，同一支队伍的数值应一致。等两边都进入第二回合，再安排并锁定一次。可以在其中一端点「演出」切换倍速，验证先播完的一端会等另一端。继续打一局时，胜负应在两边对应显示。
6. 任意一端点「退出房间」，另一端应收到断开提示并回到大厅。

同一 Wi-Fi 下两台电脑试玩时，加入者填写房主的局域网 IP，两台机器使用同一份工程和同一个 UDP 端口。房主先尝试通过 `ipconfig` 确认正确网卡的 IPv4 地址。跨网络连接还要确认两台电脑之间可达。

## 复跑自动验收

从项目根目录开两个 PowerShell 标签页。先运行房主命令，再运行来宾命令。加 `--headless` 可以只看日志。带画面双开时，可在 `--path` 前加 `--audio-driver Dummy`，让两个窗口静音并避免抢占设备。端口已占用时，在两条命令的最后都附上同一个 `--port=7001`。

```powershell
# 标签页 1
& '.\.tools\godot-4.7.2\Godot_v4.7.2-stable_win64_console.exe' --path '.\battle-demo' --script tests/test_pvp_network.gd -- --host

# 标签页 2
& '.\.tools\godot-4.7.2\Godot_v4.7.2-stable_win64_console.exe' --path '.\battle-demo' --script tests/test_pvp_network.gd -- --guest
```

脚本从正常入口点开大厅、建房和加入。前两回合覆盖安排、撤销、非法计划拒绝和先后锁定，之后打到实际胜负，最后检查离房。按同一回合比较两边的 `PVP_RESULT`，其中生命、Cost、胜负、事件数和拼点结果都已按房主／来宾顺序整理。通过时两边分别输出 `PVP_PASS host` 和 `PVP_PASS guest`。

## 代码入口

- [NetworkManager.gd](../../battle-demo/scripts/pvp/NetworkManager.gd) 是 Autoload。在 Peer 1 接收计划、确认锁定、广播结果，并处理离房。
- [pvp_lobby.tscn](../../battle-demo/pvp_lobby.tscn) 是建房和加入界面，也可打开该场景后按 F6。
- [pvp_battle_rules.gd](../../battle-demo/scripts/pvp/pvp_battle_rules.gd) 在房主运行，复用现有的出牌校验、掷币、伤害、胜负和回合流程，同时处理对称的 PvP 配对和费用。
- [pvp_planning_ui.gd](../../battle-demo/scripts/pvp/pvp_planning_ui.gd) 继承现有选牌和演出界面，使用 [pvp_draft.gd](../../battle-demo/scripts/pvp/pvp_draft.gd) 保存本地草稿。
- [test_pvp_network.gd](../../battle-demo/tests/test_pvp_network.gd) 是双进程验收脚本。

## 本次验证

- Windows 本机使用 Godot 4.7.2，分别做了无窗口和 OpenGL Compatibility 有画面双进程测试。通过实际 ENet 回环连接完成对局。最后一次有画面测试打了 5 回合，房主用 ×4、来宾用 ×2，两边的 HP、Cost、拼点与胜负记录一致。
- 有画面测试使用 1100×720，游戏截图在项目内已忽略的 `battle-demo/test-output/pvp-guest.png`。截图取自房主已锁定、来宾仍在规划时。
- 20 个非渲染回归脚本通过，包括出牌、费用、地图、失衡压制及角色技能。
- 模式面向互相信任的好友，房主进程持有权威状态。真机异地、断线重连和对战平衡仍待测试。
