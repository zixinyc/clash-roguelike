# 《余烬交锋》代码全景与模块速查指南

> **为什么有这份文档？**  
> 整个工程的核心代码都在 `battle-demo/scripts/` 下（GDScript）。如果每次接手都从头翻`exploration_map.gd` 或 `battle_rules.gd`，不仅人看着累，Agent 也会浪费大量上下文。  
> 读完这份浓缩指南（约 3 分钟），你就能清楚**每个文件管什么、数据怎么流转、改功能该去哪几行、哪些自动化测试接口绝对不能碰坏**。

## 1. 一眼看懂：游戏是怎么跑起来的？

```
启动游戏 (project.godot 主场景)
   │
   ▼
【主界面 / 模式与出战设置】 battle_setup.tscn (scripts/battle_setup.gd)
   │
   ├──► 路线 A：开启林地探索（Roguelike 主玩法）
   │       │
   │       ▼
   │    exploration_map.tscn (scripts/exploration_map.gd)
   │       ├─ 地图生成：generate_floor1_grid() / generate_grid() ──► ForestMapGraph（9×7 方格）
   │       ├─ 单局状态：ForestRun (管队伍血量、Cost、1d4 行动骰、牌库实例 uid、附魔、遗物、道具)
   │       ├─ 视觉渲染：MapVisuals (阳光林野底图、丁达尔光束、晨雾、16 类矢量徽章、立体骰盘)
   │       │
   │       └─ 走到战斗节点 (BATTLE / ELITE / CENTER) 时：
   │             │  在地图层之上动态挂载 main.tscn，把 run 里的队伍、牌库、遗物传进去
   │             ▼
   │          【单场拼点战斗】 main.tscn (scripts/planning_ui.gd)
   │             │  战斗结束后调用 run.apply_battle_result() 写回血量/Cost，弹出【战后三选一】
   │             ├─ 第 1～4 层击败 Boss → 处理战后奖励 → 选一项敌方强化，再进入下一层
   │             └─ 第 5 层击败 Boss → 演出结束后自动打开远征胜利画面
   │
   └──► 路线 B：单场自由交锋 / 战术演练（直接进战斗或打木桩）
           │
           ▼
        【单场拼点战斗】 main.tscn (scripts/planning_ui.gd)
           ├─ 规则大脑：DemoBattleRules (scripts/battle_rules.gd) —— 纯逻辑，不碰 UI！
           ├─ 战场舞台：DemoBattleStage (scripts/battle_stage.gd) —— 角色站位、行动槽、连线箭头、打击演出
           └─ 手牌面板：RoleHand (scripts/role_hand.gd) + DemoCardView (scripts/card_view.gd)
```

**核心设计铁律（逻辑与画面分离）**：
1. **`battle_rules.gd` 是纯规则引擎**：它只算拼点、硬币、护盾、费用和伤害，产出一份快照 `snapshot()`（给界面刷新用）和一串事件列表 `events`（给舞台播动画用）。
2. **`forest_run.gd` 是纯探索状态机**：它只管当前在第几层、掷了几点骰子、有哪些牌和遗物，不直接画任何按钮。
3. **UI 脚本只负责“画出来”和“把玩家点击传给规则引擎”**。

## 3. 核心数据结构速查（改代码不用猜字段名）

### 3.1 角色行动槽编号规则（非常重要！）
在 `DemoBattleRules` 中，每个出战角色拥有 **3 个行动槽**：
- 第 `u` 号出战角色（`u = 0, 1, 2`）对应的三个槽位 ID 分别是：
  - **`u * 3 + 0`**：进攻槽（`category = 0`）
  - **`u * 3 + 1`**：大招槽（`category = 1`，当 `flex_attack_in_ultimate = true` 时也可放普通攻击牌）
  - **`u * 3 + 2`**：防御槽（`category = 2`，只能放 `kind == "guard"` 的防御牌）

### 3.2 卡牌实例与附魔结构（`ForestRun.card_instances`）
为了支持同名卡多张副本独立附魔和删除，牌库不仅有 `deck: Array[String]`，还同步维护 `card_instances: Array[Dictionary]`：
```gdscript
{"uid": "inst_1_3", "key": "ember", "enchant": "rune_feather"}
```
- **5 种锻台符文（`ForestRun.RUNE_META`）**：
  - `rune_feather`（轻灵：费用 -1，最低 1）
  - `rune_leech`（汲血：造成实伤 15% 治疗最低血量队友）
  - `rune_impact`（破势：拼点基础威力 +1）
  - `rune_echo`（回响：普攻 25% 概率追加 35% 次生伤害）
  - `rune_overcharge`（超频：扣自身护盾换取最高 +30% 增伤）

### 拼点概率与探索奖励

- **战斗现状** · `DemoBattleRules._clash()` 使用 `ally_clash_heads_chance`，演练默认 65%，探索由 `ForestRun.get_clash_heads_rate()` 传入 45% 到 100% 的档位值，敌方为 50%。每次拼点调用 `_roll()`，非平局则令败方少一枚硬币，直到一方归零。强制正面的铅币与水银骰子的硬币威力修正在共享 `_roll()`，ZiXi 转尾与天平平局判胜在拼点流程。伤害另走 `_attack()` 及角色专属攻击，其中一些也调用 `_roll()`。调整拼点正面率时从 `_clash()` 的我方入参接入。
- **奖励现状** · `ForestRun.move()` → `enter_node()`，有选项时由 `apply_choice()` 完成节点，战斗胜利由 `apply_battle_result()` 发放奖励。探索已分别维护 `rng`、`dice_rng`、`card_rng`。
- **跨场景接点** · `exploration_map.gd::_start_battle()` 挂载 `main.tscn`，`planning_ui.gd::new_battle()` 组装探索开战配置并调用 `start()`。返回走 `_return_from_battle()`，先收集战斗状态，再交给 `ForestRun` 结算。
- **命运石之门** · `ForestRun` 管命运掉落、每座门的领取记录、强化和跨层保留。余额上限 10，单门可领 2 点，队伍拼点正面率为 45% / 60% / 75% / 90% / 100%，升四档依次消耗 2 / 3 / 4 / 5 点。`exploration_map.gd` 展示节点弹窗，`planning_ui.gd::new_battle()` 将档位传给战斗规则。
- **验证入口** · 拼点查 `test_rules.gd`、`test_stagger_overwhelm.gd`、`test_zixi.gd`，探索与战后奖励查 `test_forest_map.gd`、`test_map_nodes.gd`、`test_stage3_deckbuilding.gd`。好友 PvP 模块有独立的 `scripts/pvp/pvp_battle_rules.gd::_clash()`（双方 65%），当前主界面提供同种子本地远征，好友实时 PvP 界面仍为占位，当前工程配置未注册 NetworkManager。

### 五层远征与敌方强化

- `ForestRun.MAX_FLOOR` 为 5。`advance_to_next_floor()` 要求 Boss 已击败、待处理奖励已结算并有合法选项，每次合法过层只写入一条 `enemy_modifiers`。
- 坚壁 +20% 生命／+5% 伤害，均势 +12%／+10%，凶袭 +6%／+16%。可复选，百分比加到基础值。`get_enemy_modifier_config()` 供 `planning_ui.gd::new_battle()` 读取，`battle_rules.gd` 初始化敌方最大生命，敌方伤害在护盾计算前放大，数值向上取整。
- 第五层 Boss 胜利由 `ForestRun.apply_battle_result()` 写回生命、Cost 和通关状态。战斗演出结束时 `planning_ui.gd` 发出 `battle_finished`，`exploration_map.gd` 自动回写并打开 `forest_victory_view.gd`。第五层普通战照常进行。
- 回归 `tests/test_expedition_victory.gd` 验证过层校验、叠加、终局和返回菜单。`tests/test_grid_floor1.gd` 覆盖过层选择界面。 [方案与预览](../任务记录/五层远征与敌方强化方案.md)

### 渲染与低负载

- `project.godot` 的 `application/run/max_fps` 将游戏限制在 60 FPS。主菜单氛围层最高 15 次/秒，探索地图最高 20 次/秒，战斗舞台空闲时最高 24 次/秒。
- 战斗覆盖探索界面时，地图暂停环境重绘。探索掷骰期间持续播放骰面，骰盘静止时由 UI 状态刷新，待掷时保留低频提示。方格节点坐标在布局变化和 UI 刷新时同步。
- `battle_stage.gd::set_state()`、鼠标输入和活动战斗仍能即时请求重绘。重绘频率属于表现层，规则结算、行动骰 RNG 和战斗事件不依赖频率。

## 5. 自动化测试护栏（改完代码必跑）

测试入口为 `battle-demo/tests/test_*.gd`，按当前文件清单选跑。本地盘点为 32 个脚本，其中 3 个文件名以 `_render.gd` 结尾，需要实际视口，1 个需要双进程和已接通的 PvP 配置。其他脚本的截图分支按各自的测试条件启用。

**特别注意以下 UI 自动化测试锁定的字段/节点名，重构 UI 时必须保留访问兼容**：
- **`battle_setup.gd` 必保属性与节点**：
  - `members: Array`、`role_buttons: Array[Button]`、`get_node("%ClearLineup")`、`enemy_picker: OptionButton`、`deck_cycle_checkbox: CheckBox`、`launch: Button`、`launch_explore: Button`、`page: Control`、`active_battle: Control`、`_toggle_card(enabled, key)`、`_selected_cards()`。
- **`planning_ui.gd` 必保属性**：
  - `battle: DemoBattleRules`、`stage: DemoBattleStage`、`hand_view: RoleHand`、`setup_button: Button`、`sound`。

### 一键验证命令（在仓库根目录 PowerShell 运行）
```powershell
$godot = '.\.tools\godot-4.7.2\Godot_v4.7.2-stable_win64_console.exe'

# 跑单个测试（例如主界面与配队测试）

Get-ChildItem -Path battle-demo\tests\test_*.gd | Where-Object { $_.Name -notmatch '_render\.gd$' -and $_.Name -ne 'test_pvp_network.gd' } | ForEach-Object {

    if ($LASTEXITCODE -ne 0) { throw "$($_.Name) failed with code $LASTEXITCODE" }
}
```
