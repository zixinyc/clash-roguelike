# 玩法设计草案 v0.1

更新日期：2026-10-26
阶段：玩法讨论，尚无可玩实现或平衡测试。

## 1. 核心体验

玩家控制一支小队，通过手牌选择技能，与敌方行动进行拼点。出牌与购买成长内容都消耗同一个 cost 钱包：花钱提高眼前战斗的把握，也会影响后续的购买能力。

想形成的选择是：“这次用便宜的牌冒险，还是多付 cost 稳妥接招？”具体强弱关系仍需通过技能设计和试玩验证。

## 2. 已确认的设计决策

以下内容来自当前讨论中用户明确作出的选择。

| 主题 | 已确认内容 |
| --- | --- |
| 战斗组合 | 手牌与拼点结合 |
| 操作对象 | 玩家控制一支小队 |
| 统一资源 | 战斗能量与金钱合并，统一命名为 cost |
| 钱包关系 | 出牌和购物真正共用一个钱包，不设置两种只同名的资源 |
| 跨战斗保留 | cost 在同一局内带出战斗，供之后购物或出牌使用 |
| 战斗收入 | 每回合有基础收入，战斗表现可带来额外收入 |
| 行动限制 | 即使 cost 足够，也存在出牌限制 |
| 失败代价 | 拼点失败返还一部分费用，具体数值由设计方案提出并测试 |

跨战斗保留不等于跨局继承。失败重开是否继承任何成长，尚未讨论。

## 3. 资源定义

`cost` 指小队共享的整数钱包余额。卡牌的“费用”指打出该牌需要支付的 cost；商店价格也以 cost 表示。

- 只有一个钱包，余额不为负数；支付前检查余额是否足够。
- 战斗结束不把钱包重置成某个固定能量值。
- 基础回合收入、表现收入和战后奖励属于不同的收支来源，需要分别记录。
- 商店里的新卡牌、升级等是候选购买内容，具体商品与价格尚未确定。

以上是统一钱包决策的文档表达；钱包上限、开局金额和战后奖励尚未设值。

## 4. 第一轮测试参数

这些参数由助手提出，用于之后做原型。用户没有逐项确认，也尚未验证它们能形成良好的经济平衡。

| 参数 | 建议起点 | 目的 |
| --- | --- | --- |
| 全队每回合出牌上限 | 3 张 | 钱多也不能无限出牌 |
| 每回合基础收入 | 3 cost | 提供基本行动预算 |
| 基础卡牌费用 | 1～3 cost | 先用小范围比较风险与收益 |
| 拼点失败退款 | 实付费用的 50%，向下取整 | 降低失败损失，保留风险 |
| 表现收入 | 每回合首次拼点获胜 +1 cost | 奖励胜利，初步限制重复获利 |
| 小队人数 | 暂建议 3 人 | 控制首版操作与演出规模 |
| 手牌组织 | 暂建议全队共用手牌与牌组 | 降低切换多套手牌的操作负担 |

“每个角色每回合最多出一张牌”也是此前的建议，尚未确认。它与“全队最多三张”是两个不同限制，后续需决定是否同时采用。

### 退款的候选细则

建议按一次完整拼点的最终失败结算一次退款，不因每次对撞失败或每枚硬币破坏重复退款。

```text
退款 = floor(本次实际支付费用 × 0.5)
```

例子：支付 1 退 0，支付 2 退 1，支付 3 退 1。零费用牌不产生退款；打折后按实付计算。以上取整方式意味着 1 cost 牌失败不返还，需要在试玩中特别观察其感受。

建议退款不恢复已使用的出牌次数，否则可能通过重复失败绕过行动限制。取消选择、未执行的排队行动、目标提前死亡和卡牌无效不等于“拼点失败”，其撤销支付方式仍需单独设计。

## 5. 回合流程候选

下面的流程用于讨论，尚未确定采用统一排队结算，还是出一张立即结算。

1. **回合开始**：发放基础 cost 收入，抽牌或补手牌。
2. **观察敌人**：展示敌方计划行动、目标及必要的威力信息。
3. **安排小队**：选择角色、卡牌和目标，检查余额及出牌限制。
4. **支付与执行**：按最终选定的交互方式支付费用，执行行动或加入队列。
5. **拼点**：双方技能比较；候选规则为败方破币并继续，直到产生最终胜负。
6. **处理结果**：结算攻击、状态、死亡、退款和表现收入。
7. **回合结束**：处理未执行的敌方行动、弃牌和持续效果，进入下一回合或战斗结算。

抽牌数量、弃牌方式、出手顺序、敌人行动消耗、无人接招时的攻击方式都仍待明确。敌方行动是否完整提前公开也是候选设计。

## 6. 一个 cost 收支例子

为了只观察经济，下例假设同一回合有三次可执行的行动；角色与行动配对暂不限定。使用第 4 节测试参数。

| 步骤 | 变化 | 钱包余额 |
| --- | --- | --- |
| 进入本回合前 | 示例起始余额 | 10 |
| 基础收入 | +3 | 13 |
| 第一张牌，拼点最终失败 | 支付 3，返还 1 | 11 |
| 第二张牌，拼点获胜 | 支付 2，首次获胜奖励 1 | 10 |
| 第三张牌，再次拼点获胜 | 支付 1，本回合不再获得首次胜利奖励 | 9 |

核对：`10 + 3 - 3 + 1 - 2 + 1 - 1 = 9`。

三张牌后，即使仍有 9 cost，也达到建议的全队出牌上限。若此时战斗结束，9 cost 带到之后的节点，另加未来确定的战后奖励；不会重置回 3。示例的 10 cost 不是已经确定的开局金额。

## 7. 需要重点验证的设计风险

### 拖延刷钱

如果每回合固定收入、余额永久带出战斗，玩家可能留下弱敌反复结束回合攒钱。每回合只奖励首次获胜，也无法解决基础收入的无限累积。

第一版需比较候选措施：战斗收入总额度、敌方随拖延增强、或限制能安全拖延的敌人行为。当前不选定某一种，也不把“收入有限制”当作已经解决。验收时必须检查：故意拖延是否比正常获胜更有利。

### 越穷越难打，越富越容易赢

没有足够 cost 时，玩家可能无法使用应对技能；过多存款也可能让昂贵技能失去取舍。需要同时测试低余额和高余额局面。

可比较低费保底行动、开战保障或低费牌供应等方案，具体方式待定。不要同时默认增加第二套战斗钱包来回避统一资源决策。

### 失败退款与结果顺序

费用打折、重复触发、目标死亡、行动取消可能导致错误退款。每个行动记录实际支付费用，且最多结算一次退款；已退款的失败不能再次赚退款。

还需决定退款能否立刻用于同回合后续出牌。即刻结算与统一队列会产生不同体验，先确定交互后再写死规则。

## 8. 原型验收场景

这些是未来实现的验收要求，本次文档阶段未执行游戏测试。

- 出牌花费与商店消费改变同一个钱包，战后余额连续保留。
- 基础收入和表现收入分别入账；同回合第二次获胜不重复发放首次奖励。
- 三张牌的测试配置下，第四张被限制，即使余额充足。
- 失败时按实付退款，向下取整，单个行动不会重复退款或返还行动次数。
- 正常速度、倍速与跳过动画得到一致的余额、硬币、生命和状态。
- 空钱包仍有可理解的应对路径；该路径的具体设计须在实现前补齐。
- 反复拖延战斗不能形成明显优于正常推进的无风险刷钱方式；措施尚待选定。

## 9. 下轮讨论入口

优先讨论玩家实际如何操作，而不是继续增加数值。

1. 全队共用手牌，还是角色各自持有手牌？
2. 安排好全队后统一开打，还是每出一张牌立即结算？
3. 卡牌限定某个角色使用，还是允许不同角色使用同一张牌？

后续再确定人数、抽牌、敌人行动、平局与经济保障规则。每轮只讨论少量相关问题，当前草案允许继续修改。
