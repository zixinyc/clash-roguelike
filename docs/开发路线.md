# 开发路线

更新日期：2026-10-26。当前仅完成初步调研与仓库文档准备。以下是建议路线，尚未进入游戏实现阶段，也没有确定工期。

## 已确认与待定

已确认方向：拼点战斗、肉鸽成长、朋友共同协作，以及使用本公有仓库保存项目。

仍待明确：玩家如何出招、是否抽牌与消耗能量、角色数量、平局规则、目标平台、美术风格，以及首版内容规模。Godot 4 是调研建议，尚未最终选定。

## 阶段 1：验证拼点规则

范围：两个单位、三种技能，支持基础威力、硬币、破币和一个明确的平局结束机制。

验收：

- 相同初始状态、操作和随机种子产生相同结果。
- 零硬币、连续平局、生命归零都有明确处理。
- 可以读出每轮为什么赢或输。
- 预览胜率不会改变正式战斗的随机结果。

## 阶段 2：做出单场战斗手感

范围：少量原创或许可素材，加入前冲、对撞、破币、追击、受击、声音与倍速。

验收：

- 玩家能辨认每次拼点的胜负与剩余硬币。
- 数字、音效和撞击时刻一致。
- 动画正常播放、加速或跳过时，最终生命和状态相同。
- 一场战斗可从开始完整走到胜败结算。

## 阶段 3：接入短肉鸽流程

范围：约五个可经过的节点，包含战斗、奖励、一个事件、一次升级和一个 Boss。

验收：

- 能从开局走到本局胜败结算，并开始新一局。
- 路线只能前往当前节点允许的下一节点。
- 奖励确实改变后续战斗中的可选策略。
- 不出现重复领取奖励或战斗结束后继续出招。

## 阶段 4：扩展构筑与内容

范围：少量新敌人、技能、状态和遗物，逐项加入并验证交互。

验收：至少有两种有效打法；新增内容不破坏已有结算顺序；规则说明与实际行为一致。

## 协作拆分建议

可以按“战斗规则”“战斗表现”“路线与奖励”“设计文档与素材”分任务，不要求每个方向固定一名成员。每个 Issue 尽量控制在一个能独立检查的结果，例如“补充三种技能的例子”，而不是“完成全部战斗”。

开始实现前，先确定第一个阶段的规则与验收。后续每个阶段完成后再调整下一阶段范围。
