# 原型架构与功能索引

更新时间：2026-11-08。以源码为准；历史计划可能描述旧版。开始实现新功能前先用 `rg` 查找已有规则、数据和测试。

## 入口与状态流

`battle-demo/project.godot` → `main.tscn` → `scripts/main.gd` → `planning_ui.gd`。UI 创建 `DemoBattleRules`，负责选牌、规划、计时、提交及播放事件。规则在 `battle_rules.gd` 内独立维护战斗状态，通过 `snapshot()` 返回公开快照；`lock_and_resolve()` 根据随机种子和已安排的行动生成事件序列。UI 按事件播放，`battle_stage.gd` 负责战场绘制与动画，`card_view.gd` 绘制手牌，`synth_audio.gd` 合成音效。

## 先找哪里

| 测试与启动 | `battle-demo/README.md`、`battle-demo/tests/`、`battle-demo/启动战斗演示.cmd` |

## 当前边界

只有本地单场战斗；尚无地图、节点推进、跨场战斗状态、商店、正式抽弃牌堆、游戏存档或网络联机。`start()` 会重置小队、敌人和 cost，地图接入时不能把它当作无损的跨战斗恢复接口。`next_round()` 是同一场战斗中的回合推进，不是地图节点推进。不要把“版本存档 ZIP”误认为游戏存档系统。

默认固定 16 张测试手牌、三名队员、两名敌人，起始 30 cost、每回合 +8；这些是当前试玩参数，不是正式经济平衡。具体实现以 `battle_rules.gd` 为准。参考 [战斗演示](../battle-demo/README.md) 和 [行动规划与速度](玩法设计/行动规划与速度.md)。

## 验证

使用项目内 `.tools/godot-4.7.2/Godot_v4.7.2-stable_win64_console.exe`（若存在）或用户提供的 Godot。检查 `battle-demo/tests/` 对应脚本；`test_rules.gd` 继承 `test_planning.gd`，避免把同一套断言算成两套独立测试。图形流程使用 `--path battle-demo -- --planning-smoke`。`test-output/` 与 `.godot/` 属于运行产物；不要作为权威设计文档。

## 地图小样补充（2026-11-08）

新增独立入口 `battle-demo/exploration_map.tscn` 和 `scripts/exploration_map.gd`，通过实例化 `main.tscn` 复用战斗；战后将生命和 cost 保存在地图场景内，地图重开或退出即重置。不是持久存档或正式 Run 系统。地图规则回归见 `tests/test_map.gd`。此前“尚无地图”的描述适用于原单场战斗入口；地图探索小样现已存在。

## 节点扩展（2026-11-08）

`exploration_map.gd` 的 `NODES` 和 `BATTLES` 是固定节点位置；`_move()` 分派节点，`_open_node()` / `_choose()` 处理营地、事件、商店，`_return_from_battle()` 处理战斗奖励，`cleared` 防止重复领取。`tests/test_map_nodes.gd` 验证经济及重访边界。行动点仅为候选，未实现。

## 自由配队与卡组

战斗演示默认入口是 battle_setup.tscn，配置逻辑在 scripts/battle_setup.gd。它把角色 ID、敌组和携带牌交给 main.tscn。地图仍直接实例化 main.tscn。battle_rules.gd 中的 create_roster、card_owner 和 available_cards 提供阵容与卡牌目录。队伍下标只用于行动与动画索引，技能归属和人物效果按实际角色识别。验证入口为 tests/test_battle_setup.gd。
