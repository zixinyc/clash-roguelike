# 开发路线

更新日期：2026-10-29。当前已完成初步调研、玩法方向讨论和本地 Godot 单场战斗演示。后续路线继续根据试玩调整，没有确定工期。当前可玩范围见[原型说明](../../battle-demo/README.md)。

## 已确认与待定

已确认方向：小队、手牌加拼点、肉鸽成长、朋友共同协作，以及使用本公有仓库保存项目。出牌与购物共用可跨战斗保留的 cost 钱包，战斗采用基础加表现收入，存在出牌限制，拼点失败部分退款。

仍待明确：正式手牌组织、角色数量、出牌限制的具体方式、平局规则、经济参数、拖延刷钱处理、最终目标平台、美术风格，以及首版内容规模。已选择 Godot 4 与 GDScript，当前采用三人共用手牌、多个分类行动格、敌方先锁定与 180 秒响应，按公开速度统一结算的配置；这些交互与数值仍可修改。已确认事项与建议参数见[玩法设计草案](玩法设计草案.md)。

## 阶段 1：验证拼点规则

进度：规则基础已验证，716 项断言通过；正式经济平衡仍待试玩。

范围：两个单位、三种技能，支持基础威力、硬币、破币和一个明确的平局结束机制。

验收：

- 相同初始状态、操作和随机种子产生相同结果。
- 零硬币、连续平局、生命归零都有明确处理。
- 可以读出每轮为什么赢或输。
- 不显示胜率；敌方卡牌在规划阶段从公开快照隐藏。
- cost 支付与失败退款按实付结算且不重复；收入与行动限制通过独立场景验证。具体测试数值按玩法草案配置，不视为最终平衡。

## 阶段 2：做出单场战斗手感

进度：本地可操作演示已完成，包含程序绘制场景和角色、拼点、破币与追击、倍速、胜败和重开。音效已合成但当前设备未完成实听验证。

范围：少量原创或许可素材，加入前冲、对撞、破币、追击、受击、声音与倍速。

验收：

- 玩家能辨认每次拼点的胜负与剩余硬币。
- 数字、音效和撞击时刻一致。
- 动画正常播放、加速或跳过时，最终生命和状态相同。
- 一场战斗可从开始完整走到胜败结算。
- 接入小队与手牌交互，验证行动分配；人数和结算方式需在实现该部分前确定。

## 阶段 3：接入短肉鸽流程

范围：约五个可经过的节点，包含战斗、奖励、一个事件、一次升级和一个 Boss。

验收：

- 能从开局走到本局胜败结算，并开始新一局。
- 路线只能前往当前节点允许的下一节点。
- 奖励确实改变后续战斗中的可选策略。
- 不出现重复领取奖励或战斗结束后继续出招。
- 战斗与购物共享 cost，余额正确保留；低余额仍有应对路径，拖延不能无限安全获利。

## 阶段 4：扩展构筑与内容

范围：少量新敌人、技能、状态和遗物，逐项加入并验证交互。

验收：至少有两种有效打法；新增内容不破坏已有结算顺序；规则说明与实际行为一致。

## 协作拆分建议

可以按“战斗规则”“战斗表现”“路线与奖励”“设计文档与素材”分任务，不要求每个方向固定一名成员。每个 Issue 尽量控制在一个能独立检查的结果，例如“补充三种技能的例子”，而不是“完成全部战斗”。

开始实现前，先确定第一个阶段的规则与验收。后续每个阶段完成后再调整下一阶段范围。

本轮优先试玩[行动规划与速度](行动规划与速度.md)，暂不开展地图实现。
