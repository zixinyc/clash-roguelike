# 架构梳理与路线地图任务

目标：降低后续 agent 重复实现战斗功能的风险，为肉鸽地图提供清楚的接入点。
范围：先核对并更新当前说明、建立代码导航，再根据用户对黑流树海参考点的回答设计地图；地图范围尚待明确。
约束：保留现有代码和历史任务记录；不创建 Git 仓库或删除文件；游戏原型当前仅为单场战斗。
步骤：核对战斗代码和旧文档；更新错误参数并创建架构索引；核对索引链接及内容；明确地图具体交互后制定地图方案并实施。
验收：入口与状态流与代码一致，现有和历史状态分开标识；地图验收标准在需求明确后补充。

## 地图小样方案（2026-11-08）

目标：可在区域内逐格探索、发现地点并进入现有战斗，再返回地图。以固定小地图验证体验，视觉为程序绘制；不是对参考作品机制的完整复刻。
约束：独立地图入口，保留原战斗演示；仅可走相邻格，首次接触揭示相邻区域；战斗胜利清除敌人，失败结束本次探索。探索中的 cost 和队员生命跨战斗保留；不做存盘、商店、随机地图和正式肉鸽平衡。
验收：不能越界或移动到非相邻格，迷雾逐步揭开；可进入战斗并在胜负后返回，胜利不能重复领奖、资源随队伍保留；终点可达并结束探索。执行规则与场景检查，明确未人工验证项。

## 结果与验证

护盾计算收拢为单一变量，战斗规则 716 项断言和角色新卡测试通过。地图小样已实现固定网格、迷雾、两处敌人、出口、进入战斗与返回、生命和 cost 跨场继承；地图集成测试和图形窗口渲染通过，实际窗口截图已检查。未完成玩家手动完整战斗验收、地图随机与持久存档；允许绕开敌人到达出口。
