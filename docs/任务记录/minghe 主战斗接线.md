# minghe 主战斗接线

## 分工与顺序

- 正在进行的角色扩卡工作继续维护 `scripts/characters/minghe.gd`、符卡目录及 UI 接线。主战斗接线先提供通用一次性增益，再在角色扩卡结束后对照当前实现接入 minghe，并通过原战斗入口验收。
- `battle_rules.gd` 中所有队员拥有各自的 `next_clash` 和 `next_damage_bonus`。不同来源按字典键相加，同来源重授覆盖。拼点开始时取出并清空拼点加成，攻击伤害首段到来时取出并清空增伤。反伤和零伤害辅助动作保留攻击增益。伤害加成走普通护盾结算。
- ZiXi 和 ZiWu 的角色模块保留独立调用时消费 `next_clash` 的行为。主引擎先消费容器，随后角色模块读到空容器，既有加成只算一次。

## 角色与主战斗接线

- 角色层提供最快存活队友、基础拼点加成、律动扣除和回声触发判定。最快队友以当前回合的行动速度为准，同速按队伍顺序，独行时跳过先声夺势。
- 引擎每回合准备完成后，向最快存活队友写入 `next_clash["先声夺势"] = 1`。回合准备阶段产生的提示随下一次结算发送。
- 引擎提供单一增益入口。符卡对友军施加有效增益时检查余音绕梁次数，触发后给同一单位下次攻击 +2，并由角色层记录律动。清音起手的拼胜律动独立于余音绕梁次数，两者都受万象同频的下回合禁获规则约束。
- 清音起手、和鸣共震、万象同频的正式键为 `minghe_prelude`、`minghe_harmony`、`minghe_omni`。已有牌库可继续携带 `minghe_opening`、`minghe_resonance`、`minghe_finale`，新旧键共享同名上限，奖励池分别只提供一份。灵韵灌注继续用 `minghe_infusion`。
- 单方面行动和 Phase 0 无实际拼点。清音起手和灵韵灌注取基础档，清音给 +1 拼点，灵韵给 +5 攻击并返 1 Cost。和鸣共震在普通槽按强化状态结算，在共有辅助槽施放基础效果。万象同频通过大招槽结算，先扣旧律动，再按扣除数量施加团队增益。
- 和鸣共震的强化资源在规划时预约。撤销、替换或行动提前中断按归属槽返还，已结算的预约落账。Phase 0 仍使用原共有辅助槽的基础牌规则。

## 验收

1. 普通队友、ZiXi 与 ZiWu 各消耗一次各来源拼点增益。攻击首段消耗增伤，后续段及反伤符合各自规则。检查实例隔离和跨回合待用效果。
2. 检查正式 `start()`、换回合、先声夺势提示和独行场景。分别跑清音与灵韵拼胜、拼败、直接使用和辅助槽。
3. 检查和鸣的预约、重放、取消、被失衡中断和结算；检查万象消耗、返费、全队增益、余音绕梁限次和下一回合禁获。
4. 用本地 Godot 运行 `test_minghe.gd`、`test_core_combat_mechanics.gd` 和现有战斗回归。探索组卡与界面入口分别由构筑测试和 `test_expansion_ui.gd` 覆盖。

## 验证结果

Godot 的 33 个无头脚本全部通过。其中 minghe 定向检查 57 项、通用战斗检查 73 项。未运行需要实际视口的渲染脚本与双进程 PvP。

标准远征使用 12 个固定种子。自动排牌的整备路线中，灰烬、长锋与 minghe 通关 11/12 局，默认队通关 10/12 局。45% 正面率下单场对荒原掠夺者与狂暴飞龙分别获胜 11/12 和 5/12 局，两队单场对烬心巨像均获胜 12/12 局。抽样脚本沿用已有排牌策略，未安排 Phase 0，结果用于初步对照。完整记录在 battle-demo/build/core-combat-refactor/minghe/balance-final-12.log。
