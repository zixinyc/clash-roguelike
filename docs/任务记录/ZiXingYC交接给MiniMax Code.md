# MiniMax Code 任务｜接入 ZiXingYC

在 Windows 工作区 `D:\游戏项目` 中完成 Godot《余烬交锋》的 ZiXingYC 角色。先读 `docs/任务记录/ZiXingYC未被遗忘的观测者设计.md` 和已有 `battle-demo/scripts/characters/zixingyc.gd`，接着读战斗规则、阵容配置和相关测试。骨架已提供属性、卡牌参数、结算配方及初始状态。以这份修订设计为准，继续实现、运行测试并交付可试玩版本。

## 玩家操作

在现有「阵容与卡组」选择 ZiXingYC，勾选所需的专属牌，然后照常选牌、选目标、安排、交锋。**整理属于具体符卡的自动结算效果，玩家通过选牌选择语料类型。沿用现有交锋与出牌流程。** 旧的独立整理弹窗图已作废。

角色 HP 40、速度 7–9。五张牌的 Cost、拼点初始值、硬币数、正面加值和基础伤害已在骨架中填写，作为首轮试玩参数。已有卡组页面负责选择角色与卡牌，数值集中在人物脚本。将占位图 `res://art/zixingyc-placeholder.png` 用于这名角色，素材缺失时使用现有占位绘制。

## 约束与接入点

- 在 `battle_rules.gd` 的 roster、`SKILLS`、`card_owner()`、`available_cards()` 登记人物及五张专属牌。保留现有角色的 ID、原默认阵容和配置页的勾选逻辑。以角色 ID 判断角色，支持单人和任意队伍次序。
- 沿用 `can_assign()`、`_solo()`、`_clash()`、`_deal_hit()` 和快照事件。普通攻击卡可以单方面攻击，拼点专属效果需要真实拼点。防御牌「被删除的昨天」与终符要求真实拼点。资源一律在规则层修改，手牌和 HUD 读取快照。
- 沿用既有 Cost 收支、破币概率、速度和拼点优先级。推理额外收入在 `next_round()` 增加，人物退场后停止结算新增收入。原型当前无全局 Cost 硬上限，以每回合额外收入 +2 为上限。其它角色的行为和素材维持现状。
- 可列出本任务文件，保留工作区里其他正在进行的改动。就地运行本地 Godot。提交或线上发布听从用户另行提出的要求。

## 结算顺序与关键规则

1. 记录真实拼点的整场胜负。胜利写入一条观测，失败写入一条反思；僵持没有胜负记忆。技能额外记忆随后计入同一个每回合 3 条上限。编号单调递增，原日志顺序持久保留。回合开始只重置写入上限计数、整理状态及回合期限的效果。
2. 未整理达到 5 条时自身拼点 −2，达到 8 条时 −4。按该次拼点开始时的未整理数量计算，最终点数与现有规则同样下限为零。整理成功立即更新后续行动的过载、检索和生成收益。
3. 「注意力机制」拼赢追加一条观测，角色仍存活且该牌实际结算时尝试整理推理语料。「自指悖论」拼赢后，若目标仍活着，施加下一次与 ZiXingYC 拼点 −2、写入关联并尝试整理检索语料。角色与目标的每次拼点开始时消耗相应悖论标记。对已经受标记或其他拼点削弱影响的目标，该牌拼胜后的攻击额外 +3；是否已受削弱在本次拼点开始时记录。
4. 「残差连接」先以已整理记忆数整除 3，再乘 2，计算最多 +10 的额外伤害。实际攻击完毕后取最早的三条未整理记忆，按骨架中的生成顺序稳定排列，生成语料。三张攻击用剩余硬币单独掷算卡牌的基础伤害，每份生成语料 +1，上限 +5，每次攻击只加一次。
5. 「被删除的昨天」拼胜获得 10 盾，使用原型当回合期限；拼败追加一条反思。已有至少 3 条已整理记忆时，对本次拼败的每段来袭伤害先乘 0.7 向下取整，再抵扣护盾。该减伤仅限本次交锋。
6. 终符在安排时要求已有至少一份语料、可拼点及尚有次数。实际拼赢并发动才消耗一次，每场至多两次。每个存活目标分别受到 `8 + 4 × 语料总数 + min(5, 生成语料数)` 的攻击伤害，照常抵盾。读发动前的层数，轰炸后保留三种语料。
7. 整理时用当下未整理记忆，允许使用这张牌刚获得的记忆。每回合至多一次成功整理。推理要求各一条并按观测→关联→反思；检索同样各一条并按反思→关联→观测；每种类型取最早的一条。生成用上述残差配方。先验证三个 ID 各异、都存在且未整理，再一次性标记三条、增加一份对应语料。失败或动作取消时保持原状态。

## 验收用例

- 开场角色、五张牌和占位图可通过配置页进入战斗。手牌区能读到未整理条数与三类计数、过载、三种语料及本轮是否已整理。选牌提示显示符卡自带配方与当前是否有足够材料。
- 记忆按获得顺序保留。若依次获得观测 #4、反思 #5、关联 #6，注意力可使用 #4→#6→#5 生成推理，原日志仍按 #4、#5、#6 排列。重复整理、重复 UI 刷新均不能再次增加语料。5 条整理后变成 2 条，后续拼点解除 −2；验证 8 条时为 −4。
- 测试注意力和防御的额外写入受 3 条上限、残差加成封顶 +10、悖论只影响指定目标与下次拼点、两份推理下一回合 +1 cost、两份检索只对该角色的对手 −1、生成加伤只应用一次。测试防御拼胜、受击减伤顺序及行动取消。
- 若拥有推理 1、检索 1、生成 1，终符对每个存活敌人造成 `8 + 4×3 + 1 = 21` 点护盾前伤害；拼输零次发动；第三次发动受限；重开清空整场记录与语料。
- 在 `battle-demo/tests/` 添加独立测试。使用项目内 Godot 4.7.2 跑新增测试，以及现有 setup、short team、planning rules、角色和两套地图回归。报告修改文件、运行命令、有效断言与仍待人工平衡的部分。
