# 运行卡顿与界面刷新优化

## 计划

- 以本地 `564487c` 为初始对照，记录同一 Godot 版本下的战斗初始化耗时、战斗状态刷新成本、地图静止和进战时的绘制次数。
- 优化范围为废林绘制、战斗规划控件刷新和复用合成音效。战斗数值与事件时序沿用当前实现。新出素材仍在 `asset/`，本轮保留素材产线，避免把运行优化和首次接入素材的成本混在同一次测量。
- 复跑相同探针、仓库已有回归和真实渲染入口，核对拖牌、敌方隐藏信息、地图点击、从战斗返回及队伍道具。

## 改动

- 林地绘制分为连线、脉冲动效、节点和文字三个绘制层。移动、回合变化和窗口缩放时刷新静态层，悬停只刷新节点层，每帧只更新脉冲层。进战暂停林地绘制并隐藏地图内容，返回时恢复。
- 战斗行动格选单按实际条目变化更新，手牌角色与分组按钮按高亮变化更新样式。卡片复用数字字体和空样式资源，战斗实例共享一份程序合成音效。咲夜等使用占位画法的角色沿用原逻辑，已有专属贴图随对应角色或敌人出场时加载。

## 验收

- Windows，Godot `4.7.2.stable.official.ed1daf0bf`，OpenGL Compatibility、RTX 5070 Ti Laptop GPU。以地图种子 42、战斗种子 42、1000×650 视口复现巨像战。基线来自 `564487c` 的独立副本，补入相同的现役 `battle-demo/art/` 后导入，PNG 校验值一致。
- 固定场景的每组 90 个绘制帧内，地图静置和进战期间的静态连线层重绘均从 90 次降为 0 次。地图可见时脉冲层继续播放。
- 相邻的 `perf-compare-2-before.log` 与 `perf-compare-3-after.log` 样本中，重复进战初始化中位数由 155.6 ms 降至 71.5 ms，同一组 30 项战斗事件的单次界面刷新中位数由 4.24 ms 降至 0.94 ms。不同批次的墙钟耗时有波动，其中一次优化后进战计时高于基线。这些结果反映局部路径的开销，整局帧时间和玩家设备的体感仍待实测。
- 22 个现有测试入口通过，其中 19 个无头、3 个真实视口。复查了地图和战斗截图，并用 1 HP 巨像场景在可见窗口完成从地图进战、自动安排、结算获胜与返回林地。套件中的拖拽测试仍有已见过的 2 个 ObjectDB 实例退出告警。声音通过 Dummy 驱动运行，听感未验收。
- 本地探针及日志位于 `battle-demo/test-output/`。Windows 控制台版可用 `--path battle-demo --audio-driver Dummy --max-fps 120 --quit-after 2000 --script test-output/performance_probe.gd` 复跑当前版。
