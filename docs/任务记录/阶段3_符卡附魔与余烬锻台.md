## 实装顺序

1. **先通交易与局内继承。** `ForestRun` 持有 `deck_enchants: Dictionary[String, String]`，通用牌全队共享，卸牌或换人时休眠，恢复时生效。同一 run 跨层保留，新 run 清空。锻台确认同时校验当前节点、待结算状态（`pending == "forge"`）、有效卡、符文白名单、旧值是否过期和余额，再一次扣 4 Cost、写映射并结算节点。每卡一个符文，覆盖无退款。取消、同词条、重复或无效确认保持原状态，淬甲和制造催化剂沿用原有结算。
2. **再接入真实战斗。** 从地图的 `_start_battle()` 经 `planning_ui.gd::new_battle()` 把有效词条快照交给 `DemoBattleRules.start()`。核对 `ForestRun.deck` 的空数组转成 `null` 的默认牌组语义，以及 `available_cards()` 的归属过滤。沿用兼容的可选配置与防御性复制，实例内计算有效属性，保持共享 `SKILLS` 原值。当前探索生命、最大生命和余额在 `start()` 后覆写，把实际开战数据接入首次规划、血线初始化与费用报价之前。
3. **逐项接符文。** 规则层处理来源、持有者与一次性触发预算，UI 用已有输入和事件流展示结果。保持单场旧调用和关闭配置时的行为及固定种子结果。局内附魔适用本阶段，磁盘存档、遗物羁绊和演出改造走各自任务。

## 阶段 3 落地记录（2026-11-21 对齐废林同名多副本卡组）

### 1. 多副本稳定实例 UID 架构
为彻底解决尖塔卡组改版后「同名多张卡牌（如 2 张守夜）」无法通过单纯卡名唯一绑定附魔的问题，完成了兼容型 UID 架构升级：
- `ForestRun.deck` 保持 `Array[String]` 外部基础接口（确保原测试与脚本 100% 兼容）。
- 内部引入 `card_instances: Array[Dictionary]`（元素为 `{"uid": "inst_1_0", "key": "guard", "name": "守夜"}`）与 `deck_enchants: Dictionary[String, String]`（键为 `card_uid`，值为 `rune_id`）。
- 卡牌获得（开局/选卡/商店）自动派发单调递增实例 UID；删牌按实例精准剔除对应附魔；换人/整备保持同步；跨层稳定继承。

### 2. 锻台附魔交互与规则落地
- **锻台界面（`exploration_map.gd`）**：
  - 锻台弹窗启用 `modal_btn_3` 为 `符卡附魔（4 cost）`（余烬不足 4 时自动置灰禁用）；
  - 新增锻台附魔独立操作面板：左侧卡牌列表直观展示当前牌库卡牌及现有符文标记，右侧 5 选 1 符文，底部实时计算并显示消耗（4 Cost）与效果预览；
  - 牌库查看器（`deck_viewer_grid`）为已附魔卡牌醒目展示紫色 `✦ 符文【<名>】<说明>` 标签。
- **战斗规则与词条生效（`battle_rules.gd`）**：
  - `DemoBattleRules.start()` 从 `evolution_config` 接收 `card_instances` 与 `deck_enchants`，在 `master_deck` 中为每张单卡注入 `uid` 与 `enchant` 属性；
  - **轻灵 `rune_feather`**：通过 `card_effective_cost()` 与 `slot_effective_cost()` 实现有效费用 -1（最低 1 费保底），全链路统一覆盖手牌报价、槽位检查、预留、锁定、失衡中断退费与拼败退费；
  - **破势 `rune_impact`**：通过 `_clash_enchant_bonus()` 实现拼点基础值 +1，并派发能力触发事件与统计记录。

### 3. 测试与视口验收
- 新增 `test_stage3_forge_enchant.gd`，包含 61 项专项断言全部 PASS（涵盖 UID 唯一性、多副本隔离、同符文防重、换符文覆盖、商店删牌单卡清理、跨层继承、轻灵减费、破势拼点与锻台 UI 流程）。
- 视口测试 `test_nodes_render.gd` 新增第 4 步视口渲染，生成截图 `battle-demo/test-output/forge-enchant-preview.png`。
- 全量 25 个自动化测试及 `--planning-smoke` 烟雾测试全部通过（25/25 PASS）。
