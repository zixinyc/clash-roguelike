# 角色扩卡协作

- 对照角色卡与当前牌池，仅补缺失符卡，保留已有同功能牌及角色数值。
- ZiWu 与 pufufu 按角色模块并行开发。主会话统一处理卡池、行动校验和战斗结算入口。Minghe 先核对并行注册状态，再补缺失部分。
- 新卡伤害使用护盾结算。跨回合盾按失效回合消耗。共有辅助槽、目标切换、资源预留和回合清理使用现有接口。
- 用固定随机条件验证卡牌效果、所有权、探索奖励池与共有辅助槽，再跑完整战斗回归。

## 已接入

- ZiWu 补齐残影步、血契借刃、独行破阵、影袭追命。原创「霜隙回身」拼胜获得跨回合盾，独行时护盾更高。
- pufufu 补齐滚圆缩壳、绒毛铺垫、蓬松替身、弹跳撞击。原创「绒灯守候」保护低血队友，拼胜附带治疗。
- Minghe 接入清单中的八张符卡。单体增益可选目标，未指定时选最快的存活队友。
- 防御和辅助牌可从规划栏放进共有辅助槽，在速度时间线之前结算普通单方效果。强化牌仍安排在个人行动槽。友军攻击单独选人和确认。
- 扩充牌的势能伤害和牌面伤害一并经过护盾。旧牌的势能规则保留。处决仍依既有专用规则执行。

使用 Godot 4.7.2 执行 `--headless --path battle-demo --script res://tests/test_expansion_ui.gd`，覆盖队友确认、指定辅助目标、撤销以及新牌势能与护盾失效顺序。

33 个无头回归脚本通过，另以 1000×650 真实窗口执行扩卡界面用例。联机测试需要 host／guest 双端，本次验证范围为单机。
