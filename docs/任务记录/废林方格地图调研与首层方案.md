# 废林方格地图调研与首层方案

2026-11-22 · 单机探索设计草案

把废林的八列连线换成可上下左右移动的方格。行动骰决定本回合能走几格，迷雾和巡逻决定哪条路值得走；踩到战斗格再进入《余烬交锋》现有的独立拼点战斗。首轮建议用一张手工摆好的 9×7 地图验证这些取舍。

## 首层建议

![9×7 废林方格地图首层预览](视觉预览/废林方格地图预览.png)

| 设计 | 首轮规则 |
| --- | --- |
| **走格行动** | 9×7 手工图。上下左右每格消耗 1 点移动力，树林和水域可以挡路。优先高亮能走的相邻格，指向已知目标时显示路线和步数。首轮点相邻格走一步，远处格用于看路线和详情。 |
| **侦察与迷雾** | 沿用普通视野一圈、哨塔增强期间两圈的规则。未探索格隐藏地点，已知格保留地形和静态地点，巡逻兽当前位置只在可见时显示。 |
| **路线取舍** | 短路接战，绕路可先拿补给或休整。预览中从 C4 走两格到 C2 的命运石之门，或向东走三格到 F4 的普通遭遇。门沿用命运系统已有方案，首层留一条无强制战斗的到门路线。 |
| **遇敌与返回** | 保留每次结束回合时的巡逻移动。走进战斗格立即停下并进入拼点。结算战利品后继续在原处探索，地图状态和剩余行动力以 `ForestRun` 为准。 |
| **层末目标** | 建议在方格首层把「击破烬心祭坛 → 拿烬核 → 实际走到归途石门」做成一段可玩的撤离路线。当前实现里，祭坛或出口都能触发首领，战胜并处理奖励后就能打开下层弹窗。这项节奏调整需与方格玩法一起确认。 |

## 接入顺序与验收

1. **先做固定首层。** 在 `forest_map_graph.gd` 增加从 `Vector2i` 到地点 ID 的索引。每个可走格仍是 `MapNode`，根据上下左右相邻格建立 `MapEdge`，空地可先复用 `PASSAGE`。并列保留旧生成入口供回归对照。现有 `exploration_map.gd` 顶部还保留一套硬编码格子和 `_move()` 兼容接口，可读作本地参考，正式路径仍经 `ForestRun.move()`。
2. **打通交互与战斗回跳。** 在 `exploration_map.gd` 调整 `_on_map_canvas_draw()` 和 `_on_map_canvas_input()`。用现有的骰盘、徽章和节点弹窗。保留 `run.move()` → `enter_node()` → `_start_battle()` → `apply_battle_result()` 的链路；处理巡逻遭遇时区分「击退巡逻兽」和「结算地块」，避免巡逻抢先清掉事件格。若采用实际撤离规则，把领取／跳过卡牌及返回战斗后的楼层弹窗统一改为由抵达归途石门触发，校验 `advance_to_next_floor()` 的前置条件。
3. **固定图好玩后再加种子。** 先放入口、命运石之门、烬心祭坛和出口，检查主任务可达，再放阵地、行商、营地和巡逻闭环。对同一层种子检查生成结果一致，并检查到门路线没有战斗点或巡逻起点阻断、绕行有收益、出口可从祭坛抵达。捷径可先做成相邻格的隐藏通道，明确情报成本。

| 验收场景 | 应看到的结果 |
| --- | --- |
| 掷出 3 点，从 C4 依次向 C3、C2 走 | 到命运石之门时剩 1 点移动力。点斜格、树林或超距目标不会移动，也不会扣行动力。 |
| 从 C4 向东走 3 格到 F4 | 进入普通战，结算和奖励关闭后仍在 F4。再次踩已清理的格子不会刷新同一场战斗或奖励。 |
| 前往哨塔后离开视野范围 | 探索过的地形继续显示，视野之外的巡逻兽位置隐藏。 |
| 带烬核前往归途石门（采用建议规则时） | 祭坛结算后能继续在地图上走，抵达出口才可进下一层。生命、牌库、道具和遗物正常跨层。命运接入后同时验证它的跨层保留。 |

开发阶段用 `test_forest_map.gd`、`test_map_nodes.gd`、`test_stage3_deckbuilding.gd`、`test_map_render.gd` 做回归，再找一局实际试玩对比走直路和先探路的回合数、战斗次数和战前资源。格数、视野距离、撤离距离都是首轮试值。
