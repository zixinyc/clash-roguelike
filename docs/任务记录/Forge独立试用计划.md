# Forge 独立试用计划

日期：2026-11-01。状态：基础试用已完成，图形界面编辑与战斗规则接入尚未完成。

目标：评估现成 Forge 是否适合《余烬交锋》的技能资料库、节点拼效果和编辑后测试。

范围：在 .tools/forge-trial 内准备官方发布包及项目级便携依赖，不修改 battle-demo；使用官方示例验证图谱与运行，再做最小规则衔接验证。遵循 karpathy-guidelines，仅添加验证所需代码。

步骤：核对实际发布版本和依赖；准备独立环境；构建、导入、运行官方示例；验证编辑保存重载及效果执行；检查与拼点、cost 及确定性结算的衔接；记录证据和采用建议。

验收：真实运行而非仅阅读 README；报告图谱编辑与保存测试结果、执行结果及原规则衔接程度；有截图或可复查日志；区分通过、失败与未验证。若发布版尚无文档中的图谱能力，如实记录版本差异，不用自制界面替代。

清理：删除成功解压的下载压缩包和无用临时文件，保留可重开的试用工程、便携依赖、日志和验收截图，供用户体验；不删除已有工具。

## 实际验收

- Forge v0.5.0、Godot 4.7.2 .NET 和 .NET SDK 8.0.427 已放入 `.tools/forge-trial`，Godot 与 SDK 官方 SHA-512 校验通过。项目构建成功，0 错误、0 警告。
- 官方治疗图谱通过程序化加载、修改名称、保存和忽略缓存重新加载：4 个节点及 3 条连接保留；这不是鼠标编辑图谱的验收。
- 在独立工程中实际运行官方治疗技能：角色站火堆受伤，生命从 80 恢复到 100，法力从 100 降到 75。退出时控制台仍报告 ObjectDB 实例和资源未释放，尚未定位；Camera2D 有物理插值提示。
- C# 代码可调用复制的现有 GDScript 战斗规则并读取初始 cost=12；未验证 Forge 图谱触发拼点、破币、扣费及同种子结果一致性，不可视为战斗系统已经接入。
- 编辑器能够启动并显示 Statescript 面板；自动化尝试资源搜索时输入未生效，因此未完成鼠标连线编辑与图形界面保存验收，也没有图谱截图。
- Godot 的 SDK 路径读取在中文路径下出现乱码，使用 Q: 目录别名后可导入；图形启动日志仍有文件系统类型查询错误。已添加试用启动脚本，若 Q: 被占用会停止；该路径别名仍是试用环境的限制。
- 校验解压后已删除本次三个下载压缩包，保留试用工程、便携运行环境、测试代码及日志。原 battle-demo 未更改。

## 选型判断

Forge 已证实具备节点图资源和可执行技能的基础能力，值得继续评估。其 .NET 环境、图形编辑器实际体验、退出资源提示以及与原战斗结算的衔接仍需解决，因此暂不能建议直接正式接入或断言完整满足需求。
