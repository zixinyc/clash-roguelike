# 《余烬交锋》战斗演进审查与阶段提示词

2026-11-18 · 对照方案 `DESIGN-2026-COMBAT-AUGMENT-JUICE`、本地 `5957254` 及审查期间工作区。以下数值供首轮试验，规则在阶段 1 确认后进入实现。

**审查结论：原案应修订后再实装。** 失衡把血线、行动损失和额外承伤绑在一起，单人队与单 Boss 都可能在一次坏结果后失去反制窗口。回响需要先解决锁定后如何使用的问题。压制、破势、重掷和速度削减同时上线，会很难识别哪一层反馈造成滚雪球。先验证战斗规则，再试构筑收益，最后用真实场景验收演出。

两个可复算的对照，均忽略角色、遗物、护盾和特殊被动。

- 双方都用二币 `ember` 时，逐次投掷并让败者掉一币，按我方正面率 65%、敌方 50%、平局重投枚举，最终胜率约 71.45%。单给我方 +2 拼点基础或单给我方平局胜出，本例都到 88.34%。当同配置的币值差是 3 的整数倍时，+2 已把平局纳入优势，因此本例两者一起装也为 88.34%。其他牌对仍须枚举。数值以忽略第 100 次平局兜底的分布计算。
- 单币 `marisa_spark` 对满三币 `nova`，正面点数 20，反面 0，需连续三次正面才赢，胜率为 `0.65³ = 27.46%`。若破晓带三币进入攻击且另掷正、正、反，其三段原伤为 10、14、14。40 HP 角色原本剩 2 HP。按原案第二段跌破 20 HP，第三段升到 21，角色退场。若再叠加穿透压制或第二次敌方行动，风险会继续扩大。这是规则反例，不能用它代替实战死亡率。

每次发送「共同开场」和对应阶段的代码框，并附上一阶段产出的路径。按 **0 → 1 → 2 → 3 → 4 → 5 → 6** 派发。阶段 3 先打通最小持久化，再接符文，阶段 4 先确认掉落来源，再接羁绊。`battle_rules.gd`、`planning_ui.gd`、`forest_run.gd` 当前都有重叠工作，等前一阶段交接后再开下一项实装。阶段 0 和 1 可先做，阶段 2 起以用户确认的规则、范围和界面预览为输入。

### 阶段 2 · 失衡、压制与回合状态机

```text
输入为阶段 1 已确认的规则。修改 battle_rules.gd 的 planning/resolve/next_round 及相应用例。为战斗演进规则提供显式配置，旧调用缺省沿用原行为和固定种子的 RNG 消耗。先实装并验证失衡，再单独启用压制。沿用锁定后一次结算，保留配对、速度顺序和技能所有权。

首轮候选：持续至触发当回合结束。血线用前 HP >= 50% 且后 HP < 50%，每单位每战最多一次；低血入场、满盾抵扣、致死与借费自残不触发。拼败记同回合两次独立最终败局，平局重掷、破一枚币和单方面攻击不计。让一次多段/多目标技能先完成全部命中，再触发失衡，给同一行动内两个条件去重。下一回合开始解除，恢复的这一回合免疫再次失衡，恢复预览必须能解释免疫期。原案的护盾清零与 150% 真伤改为后续敌对主技能 +20% 并按原流程抵盾，按段向下取整，另记录实际额外伤害。若玩家侧 P95 承伤或连续倒地仍明显增加，先测玩家侧 +10% 或只有行动压力的版本。清数值状态和清视觉各由所属层负责。

如确认保留打断，普通单位最多熄灭时间线上首个未执行、未配对的攻击格/大招格，保护已锁定迎击和防御；玩家取消后至少剩一个可执行的原定动作，Boss 保留行动。空行动不凭空补牌。跳过时释放对应的 ZiXi 等资源预留，原规划只退实际已付费用一次，原拼败卡仍按既有规则退半费。对魔理沙借费说明退款是否含已扣生命；建议只退该格有效 Cost，借费生命仍按锁定时支付。保持目标有效性和排程顺序，不把取消迎击变成额外的敌方单方面攻击。记录跳过原因和结算状态。

压制用决定整次胜负的最后一掷，D=胜者−败者，D>=6 时一次追加 min(3, floor(D/3)) 点可抵盾伤害。主技能结束后对仍活着的原对手结算，训练沙包和纯防御获胜排除。压制独立记录，禁止递归、参与汲血/回响或计作另一场拼败。首版建议暂缓减速。若批准纳入，败者的下一回合速度上限 -1 且不低于下限，同回合只记录一次，生成全部基础格和补格后消费，同看拦截判定与咲夜时停。

验收：固定投掷覆盖两个触发同现、恰好 50%、低血入场/治疗跨线再受创、多币跨线、两个独立拼败、首末行动、护盾和盾后穿透、致死、双侧失衡、对手退场、单/双人补格、咲夜时停、ZiXi 强化预留、ZiXingYC 记忆与巨像奇偶回合。对 D=5/6/9/极端值、平局判胜、沙包和无伤攻击做断言，确认胜负与胜利奖励只有一次。跑回归及阶段 0 同种子对照，交付事件字段与稳定顺序供后续演出消费。
```

### 阶段 3 · 锻台交易、附魔生命周期与五枚符文

```text
输入为阶段 1 的锻台预览与阶段 2 的战斗结算约定。先打通 ForestRun 持久化和探险入口，再让五枚词条逐个可测。在当前一牌型一槽的配置下，run.deck_enchants 用 Dictionary[String, String] 语义，稳定 card_key → rune_id；共用牌全队共享附魔。暂时换人或卸牌时词条休眠，换回来恢复。跨层保留同一个 run，开新 run 清空。校验默认 deck 的空数组语义及 available_cards() 的过滤，词条快照只把当前有效的牌交给战斗。未来若支持两张同名卡，用稳定 card_instance_id 区分并迁移旧映射。当前只加局内状态，磁盘存读档单独立项。

按以下首轮值实现已批准的词条，所有倍数向下取整。所有词条基于明确的行动来源、持有者和一次性预算。
1. 轻灵 rune_feather：有效费 -1，首版最低 1，原本 0 费仍为 0。极限火花 5→4 仍消耗原火花，牌的原始 kind 和 cost 继续供领队被动、限制和演出使用。验证长锋原始 3 费门槛、魔理沙借费、套装优惠叠放。累计划费要与牌面、自动安排、换目标、撤销、锁定和拼败退款共用同一报价。

3. 破势 rune_impact：只加 +1 拼点基础。首版保留原平局体系。测试有无天平时的常规平局、必然平局、重掷终止与纯防御牌的适用性。交付各档胜率和平均伤害的变化。
4. 回响 rune_echo：首轮使用 25% 的自动余波，只对普通单目标攻击、主目标实际损血且仍存活时在技能结束判定一次，全队每回合至多生成一次。余波按主目标实损 HP 的 35% 计算并再次正常抵盾，不复制角色效果、费用、火花、记忆、遗物、击杀返费、附魔和胜利触发，统一走退场和胜负判定。使用独立且可复现的派生 RNG，或给出事件顺序与共享 RNG 的可接受差异。明确次生扣血是否触发血线；推荐沿用同一 HP 阈值规则但不触发拼败。若合同选了手牌版，先设计新的再规划阶段、唯一实例、额外行动额度、0 费退款和过期清理，在既有一次锁定模式中仅展示手牌不足以验收。
```

### 阶段 4 · 遗物羁绊、同调与费用闭合

```text
输入为确认的套装部件、阶段 3 共享费用报价与有效伤害上下文。优先核对真实掉落、商店、锻台与独立战入口。两种消耗品 ID 不参与永久三件套；经确认可替换为现有合适遗物或提供独立的永久 ID 与获取途径，保留药品使用语义。只按唯一 relic ID 激活一次，验证 2/3 件、重复、跨层、组件奖励池与描述一致。

余烬狂欢候选：首轮一次、最低费用 1、减 1 Cost。折扣在规划阶段使用固定可追溯归属，例如提前标为本队首个获得减免的有效付费安排，换牌/撤销要重算并更新预览，锁定后不被后续打断转给第二张。优先采用地图基础战利品 +25% 向下取整，现有余烬袋 +4 单独结算，只保留一个加成拥有者。对已花/未花费用、战败、重复回写及探索累计余额做账，防止对带回余额一起乘。

天命在握候选：每队每回合首枚自然反面的拼点币重投一次。验证玩家单枚 65% 掷币独占重掷时变为 87.75%，多币与高 power 统计单独跑。先确定玩家与敌方 roll side，并确定现有道具保底、ZiXi 尾面转换、锁正与重掷顺序。推荐先处理道具保底，再允许已存在的角色转换消费自然反面，最后由套装重掷仍未处理的首枚自然反面；攻击币与敌方不消耗套装。重掷结果不会再次触发。首轮疑虑速度 -2 暂缓，先测试它对拦截窗口的影响。

荒野行者候选：每层第一次真正抵达新节点时全队存活者 +1 HP。回头、停留、失败移动、点击确认重复回调都不给收益。营地及神龛仅治疗量 +25% 向下取整，现金、最大 HP、行动点、情报、清疲劳不放大。说明干粮加成与套装的计算顺序，经确认后一并写入 UI。

同调按队友存活、真实行动、目标 ID 与可消费的标记结算，先用每队每回合同调各一次的上限。优先验四组：咲夜成功使同一个敌人获得虚弱，魔理沙下次普通攻击主目标 +2（大招先排除，击杀返费首测至多 +1）；灵梦本回合实际为灰烬加盾且灰烬活着，给予 1 层现有蓄势；灰烬用白名单重击打到同一存活目标后，长锋下一次命中最多穿过 4 盾；ZiXi 真正增加因果律才允许给 ZiXingYC 一份与现有整理预算共用的缺失语料进度，锁正仅在独立验证后纳入，并只给确认的角色与下一枚有效拼点币。检查时间先后、目标变化、双角色触发、三人叠两组、死亡、满资源、回响与因果律/语料递归。基于现有牌表的替代触发也可提交确认，例如秒表拼胜后给此次对手挂一次连携标记，封魔阵拼胜后给灰烬一层现有蓄势。重击由阶段 1 合同列出技能白名单；没有经过确认且可复现的触发源时，暂缓对应连携。

回归重点是现有角色专属被动、道具一次消费、战斗回写和固定种子。用逐项启用及极端叠装对照，交付套装可达性、成套率、收益尾部和最低/最高收益的队伍组合。
```

### 阶段 5 · 演出时钟与高倍速验收

```text
输入为已确认的图片预览、阶段 2 决胜/压制/失衡事件和阶段 3 的原始牌数据。改 planning_ui.gd、battle_stage.gd 与所需音效接点。规则一次结算并输出 typed/有明确字段的事件，UI 只用事件数据（action_id、来源、目标、final、margin、damage、stagger 等）安排展示。角色名、攻击类别和原始费用来自该动作。使用实际开始释放的 ultimate 且原始 cost>=4，只播一次 Cut-in；轻灵减费仍能播，取消、打断和纯付费事件不播。魔理沙全体命中共用一次切入。

复用现有 _contact() 的停留预算，别在每次破币外层叠暂停。首轮候选为最终决胜分差 <=2 或 Overwhelm 才走微顿挫，同一拼点最多一次。×1 可见接触保留约 60ms，×2 把约 30ms 并入接触表现，×4 用一帧接触闪或合并镜头，额外等待为 0。Cut-in 的 250ms 作为 ×1 介绍预算，×2 约 125ms，×4 将约 60ms 的横幅与启动动作重叠，可对多招合并；确保短横幅仍能露出完整技能名，战报保留读数。碎晶、飘字尽量并行，低动态选项关闭震屏、强闪与全屏暗化，保留状态标签。飘字按实扣 HP 与护盾分开显示，只给契约定义的增伤打特效标签。

分别记录规则/规划时钟、倍速控制的本地演出时钟、无缩放的 UI 和设备音频播放。围绕实际安装版验证 ignore_time_scale 定时与 Tween API，检测 ×1↔×4 中途切换时的完成语义。不要修改 Engine.time_scale 或冻结整棵树。接触音、闪光、飘字同一个标记触发。倍速时音效按接触点启播并抑制过密重复，避免等完整音频播完才结算。不晚于预览承诺的时间恢复输入。重开、离场、跳过、重复 await 及多段/AOE 路径必须清理在途 Tween/Timer、暗化、震屏、音源及 busy 状态。

验收：同种子在 ×1/×2/×4/跳过的最终快照、战斗事件和 RNG 一致。实际视口录制同一低分差、多平局和多大招场景，取接触和音频触发时间戳、回合解锁耗时、取消时资源清理和 1000×650 可读性。对照无新 FX 的 ×4，试验目标为长回合耗时增幅不超过 10%，报告实际帧率与样本。声音从真实输出实听并记录；若只有无头或 Dummy 驱动，明确无法评价听感。
```

### 阶段 6 · 集成试玩，决定默认开关

```text
复跑阶段 0 的清单和同种子场景，再经正常启动入口做两层废林纵向验收。覆盖三类人数及第一位角色低血、锻台确认到实际卡牌、换人换回、巨像打断、遗物凑齐、战后 HP/Cost/道具、跨层和重开。保留开关关闭时的既有预期。对照逐个启用和全部启用，分别报告首次跌线同回合退场率、未执行动作原因、Boss 空过、P95 承伤、符文治疗与额外伤害、回合时长、Cost 累计斜率和实战音画体验。

验收硬条件：无复制递归、无一笔交易多扣/多送、无特效改变规则/随机序列、无因失衡删除玩家最后一个可执行计划、所有原定测试入口证据可复查。平衡是否通过，根据阶段 0 基线和阶段 1 确认的各场景目标判断。把仍影响验收的长尾分布、主观试玩分歧和文档缺口记录在任务文档。汇总向团队建议保留/调参/暂缓的开关及对应回退方法，由用户确认默认开启的范围。
```
