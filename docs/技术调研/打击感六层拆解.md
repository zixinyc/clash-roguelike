## 0. 一页速查

### 结论

视频教的是「打击感不是某一个特效，而是六件小事同时发生」。这六件事每一件代码都很短（视频原话：6 层效果 = 6 行调用），但叠在一起观感完全不同。作者原话：每一层都很小，叠起来就是质变。

### 六层清单

| 序号 | 名字 | 视频原话（画面文案） | 作用 |
| --- | --- | --- | --- |
| 01 | 顿帧 HIT STOP | 命中瞬间，整个游戏停住 0.1 秒 / 短到看不清，但手一定感觉得到 | 给「力量落地」一个瞬间的实感 |
| 02 | 震屏 SCREEN SHAKE | 镜头要跟着一起摇 / 用 trauma² 衰减：轻击微颤，重击猛震 | 让整个画面参与这次打击 |
| 03 | 受击闪白 HIT FLASH | 被打中的那一帧，整个变白 / 只亮 0.1 秒，却是最清楚的「打中了」 | 一帧之内把「命中」说清楚 |
| 04 | 击退 + 形变 KNOCKBACK & SQUASH | 力量必须有去处 / 先压扁、再弹回 —— 挨打的东西要「挨得动」 | 让力量有去处，敌人不再是贴图 |
| 05 | 粒子 + 跳字 PARTICLES & NUMBERS | 把能量炸出来 / 火花 + 冲击波 + 伤害数字，眼睛才有落点 | 给眼睛一个落点 |
| 06 | 分层音效 LAYERED SFX | 打击感，一半在耳朵里 / 低频重击 + 中频碎裂 + 高频风声，三层叠成一响 | 补上画面给不了的一半信息 |

### 《余烬交锋》先做这三件（都不用新素材）

1. 顿帧 —— 命中瞬间全局停 0.08～0.1 秒。改动最小，收益最大。
2. 形变挤压 —— 受击者先压扁再弹回（纯 scale 动画）。
3. 三层打击音 —— 用现有程序合成器做「低频重击 + 中频碎裂 + 高频风声」三个音同时播，每次音高随机 ±10%。

需要角色动画或美术素材才能做的（先别排期）：挥击动作本身、受击方向倾倒、刀光拖尾、真粒子特效。

### 现状对照（一句话）

我们已经有：闪白、轻微抖动、击退、放射线火花、飘起来的伤害数字、单音打击音效。
我们缺：顿帧、形变挤压、分层音效、真粒子与冲击波环、连击计数。

## 2. 视频整体思路与六层

### 2.1 作者的主张（画面原文）

- 开场：「没有打击感」（BEFORE · NO JUICE），文案是「但是……像在吹空气」「差的，就是下面这 6 层 ↑」，配套的 enemy.gd 只有两行有效内容：`hp -= dmg` 和一行注释「……然后就没有然后了」。演示画面里敌人站着不动，头顶只冒一个「？」气泡。
- 紧接着切到「有打击感」（AFTER），同一把刀、同一只怪。
- 结尾定格：「打击感 ≠ 一个特效」「是 6 个细节叠在一起」；然后是 BEFORE（0 层）与 AFTER（6 层全开）的同屏对比 —— BEFORE 画面里角色挥了一刀，敌人只是站着；AFTER 画面里敌人整个变白炸开、迸出火花、跳出伤害数字 26 和 43、血条掉了一大截。

### 2.2 六层逐项

#### 01 顿帧 HIT STOP（0:11–0:18）

- 是什么：命中那一瞬间，把整个游戏的 `Engine.time_scale` 设成 0，让世界静止 0.1 秒，再恢复。
- 画面表现：DEBUG 浮窗显示 `Engine.time_scale = 0`，旁边一张折线图横轴是「现实时间 →」、纵轴是「游戏时间」，顿帧期间游戏时间的曲线变平、现实时间继续走 —— 作者用这张图说明「世界停了，但现实没停」。
- 作用：短到看不清，但手一定感觉得到。它是「力量落地」的那一下的锚点，其余五层都是围绕它加料。

#### 02 震屏 SCREEN SHAKE（0:19–0:26）

- 是什么：给相机一个「创伤值」trauma，命中时加 trauma，每帧按平方衰减并加随机偏移。
- 画面表现：DEBUG 浮窗显示 `Camera2D.trauma` 的数值和一根条形指示；镜头整体在抖。
- 作用：让整个画面参与这次打击，而不是只有被砍的那个东西在动。平方衰减是关键：轻击只是微颤，重击才猛震。

#### 03 受击闪白 HIT FLASH（0:27–0:34）

- 是什么：给角色挂一个 canvas_item 着色器，用 `flash` 这个 0 到 1 的参数把颜色往白色混；命中时从 1 快速 tween 回 0。
- 画面表现：DEBUG 浮窗显示 `shader flash` 的数值条；命中那一帧史莱姆整个变成纯白，然后恢复红色。
- 作用：画面上「打中了」三个字最清楚的一帧。持续极短（文案写 0.1 秒，代码里是 0.12 秒）。

#### 04 击退 + 形变 KNOCKBACK & SQUASH（0:35–0:42）

- 是什么：命中时给受击者一个朝攻击方向的速度，同时把它的 scale 压成扁的（1.4, 0.6），再用弹性 tween 弹回 (1, 1)；速度每帧向 0 收敛。
- 画面表现：DEBUG 浮窗显示 `enemy.scale` 从 (1.4, 0.6) 弹回 (0.99, 1.00)，以及 `velocity.x` 的数值。
- 作用：力量必须有去处。挨打的东西要「挨得动」—— 又是位移又是变形，玩家才相信这一下打实了。

#### 05 粒子 + 跳字 PARTICLES & NUMBERS（0:43–0:50）

- 是什么：命中时实例化一个 GPUParticles2D（one_shot）当火花，再实例化一个伤害数字标签放到受击点上方 80 像素。
- 画面表现：DEBUG 浮窗显示 `GPUParticles2D` 的活跃粒子数（截图时是 60 个）；演示画面里火花四溅、伤害数字跳出来。
- 作用：把能量炸出来。火花 + 冲击波 + 伤害数字，眼睛才有落点 —— 没有这层，前四层的冲击会「散掉」。

#### 06 分层音效 LAYERED SFX（0:51–0:58）

- 是什么：三个 AudioStreamPlayer2D 分别装低频重击、中频碎裂、高频风声三段素材，命中时三个一起播，但每次音高随机 ±10%。
- 画面表现：DEBUG 浮窗显示 `AudioStreamPlayer2D ×3` 和三条波形，标注「低频·重击 / 中频·碎裂 / 高频·风声」。
- 作用：打击感，一半在耳朵里。随机音高让每一次命中都不完全一样，避免机械重复。

### 3.2 六层怎么配合

视频里作者把六层拆开单独讲，每层都是独立触发。真正的「合体」在 0:59–1:00 那段汇总代码里，六层在同一个被命中回调里按顺序调用，作者的意思是「同时发生」。

从代码能读出的时间信息只有各层自己的持续时长：

- 顿帧：0.1 秒（硬停，之后恢复）
- 闪白：从 1 tween 到 0，用时 0.12 秒
- 形变弹回：0.4 秒，弹性缓动
- 粒子：one_shot，发完即止
- 音效：素材本身长度（视频没给数值）

### 3.3 视频没有讲的部分（重要）

- 没有「准备 → 挥击 → 命中 → 收尾」的四阶段编排。作者全程只讲「命中瞬间」这一帧怎么加料，没有讲起手动作、收刀动作、招式之间的间隔。
- 没有讲六层之间的先后顺序和间隔（比如顿帧结束后才播音效、还是顿帧期间就播）。汇总代码是同帧并发调用。
- 没有讲不同强度（轻击/重击/暴击）怎么分层套用，只在震屏那段的文案里提了一句「轻击微颤，重击猛震」。
- 没有讲多段连击时怎么错开（每段都满特效会不会糊）。

这四条正好是《余烬交锋》要自己定的东西，第 6 节给了建议。

## 4. Godot 具体做法

下面代码逐字摘自视频（作者：还没醒er，BV1kvWg6aEdP），照抄是为了对照实现。

### 4.1 视频展示的代码

#### 01 顿帧 — hit_stop.gd（0:11–0:18）

```gdscript
# 命中时调用：让整个世界停一下
func hit_stop(duration := 0.1) -> void:
    Engine.time_scale = 0.0
    await get_tree().create_timer(
        duration, true, false, true).timeout
    Engine.time_scale = 1.0
```

#### 02 震屏 — camera_shake.gd（0:19–0:26）

```gdscript
extends Camera2D
var trauma := 0.0

func shake(amount := 0.5) -> void:
    trauma = minf(trauma + amount, 1.0)

func _process(delta: float) -> void:
    trauma = maxf(trauma - delta * 1.5, 0.0)
    var s := trauma * trauma
    offset = Vector2(randf()-0.5, randf()-0.5) * 60.0 * s
```

#### 03 受击闪白 — hit_flash.gdshader + enemy.gd（0:27–0:34）

```gdscript
shader_type canvas_item;
uniform float flash : hint_range(0.0, 1.0);
void fragment() {
    vec4 c = texture(TEXTURE, UV);
    COLOR = vec4(mix(c.rgb, vec3(1.0), flash), c.a);
}
```

```gdscript
create_tween().tween_property(material,
    "shader_parameter/flash", 0.0, 0.12).from(1.0)
```

#### 04 击退 + 形变 — enemy.gd（0:35–0:42）

```gdscript
func take_hit(dir: Vector2) -> void:
    velocity = dir * 700.0              # 击退
    scale = Vector2(1.4, 0.6)           # 先压扁
    var tw := create_tween()
    tw.set_trans(Tween.TRANS_ELASTIC).set_ease(Tween.EASE_OUT)
    tw.tween_property(self, "scale", Vector2.ONE, 0.4)

func _physics_process(delta: float) -> void:
    velocity = velocity.lerp(Vector2.ZERO, 10 * delta)
    move_and_slide()
```

#### 05 粒子 + 跳字 — hit_fx.gd（0:43–0:50）

```gdscript
@export var sparks: PackedScene      # GPUParticles2D
@export var dmg_label: PackedScene
func spawn_hit_fx(pos: Vector2, dmg: int) -> void:
    var fx := sparks.instantiate()
    fx.global_position = pos
    fx.emitting = true                 # one_shot
    add_sibling(fx)
    var num := dmg_label.instantiate()
    num.text = str(dmg)
    num.global_position = pos + Vector2(0, -80)
    add_sibling(num)
```

#### 06 分层音效 — hit_sfx.gd（0:51–0:58）

```gdscript
@onready var thump: AudioStreamPlayer2D = $Thump    # 低频
@onready var crack: AudioStreamPlayer2D = $Crack    # 中频
@onready var swish: AudioStreamPlayer2D = $Swish    # 高频
func play_hit() -> void:
    for p in [thump, crack, swish]:
        p.pitch_scale = randf_range(0.9, 1.1)  # 每次略不同
        p.play()
```

#### 全部叠加 — enemy.gd（0:59–1:00，逐字）

```gdscript
func _on_hurtbox_hit(dir: Vector2, dmg: int) -> void:
    hit_stop(0.1)              # 01 顿帧
    camera.shake(0.6)          # 02 震屏
    flash()                    # 03 闪白
    take_hit(dir)              # 04 击退 + 形变
    spawn_hit_fx(position, dmg) # 05 粒子 + 跳字
    play_hit()                 # 06 音效
```

### 4.2 视频用到的节点与引擎特性

- Camera2D（用 offset 做抖动，不是 position）
- canvas_item 着色器 + 材质参数 `shader_parameter/flash`
- GPUParticles2D（one_shot）
- AudioStreamPlayer2D ×3（分层音源，用 pitch_scale 做随机化）
- Tween（弹性缓动 TRANS_ELASTIC + EASE_OUT）
- Engine.time_scale（全局时间缩放）
- get_tree().create_timer() 的第四个参数 ignore_time_scale

### 4.3 我补充的部分（视频里没讲，我加的）

下面这些是我的补充，不是视频内容：

1. create_timer 的四个参数含义是 `(时间, process_always, process_in_physics, ignore_time_scale)`。视频代码里最后一个 true 是关键：只有忽略 time_scale，定时器才会在世界被冻住时继续走，否则恢复语句永远执行不到（死锁）。
2. 顿帧会影响整个 Godot 树，包括界面动画、粒子和 tween（tween 默认也按 time_scale 缩放）。视频没提这一层影响，也没说顿帧期间要不要屏蔽玩家输入。
3. 闪白着色器要求每个受击者有独立的材质实例，否则所有敌人会一起闪。视频没提。
4. 粒子那层的 GPUParticles2D 具体参数（amount、lifetime、explosiveness、initial velocity）视频完全没展示，只在 DEBUG 浮窗里看到活跃粒子数是 60。
5. 音效素材从哪来、音量、是否随机播放、是否要同时播两遍打击音，视频都没说。
6. 视频的震屏作用在 Camera2D 上。如果舞台是自绘的 Node2D（没有相机），就要改成作用在舞台根节点的偏移上。
7. 我没有在视频里看到任何资源文件、示例工程或素材的下载入口，所以不能保证照抄就能跑出同样效果。
8. 我也没有看到作者对「顿帧该多长」给出依据，只有 0.1 秒这个值和「轻击微颤，重击猛震」这句定性描述。

### 4.4 视频代码里的一个笔误

汇总代码里写的是 `spawn_hit_fx(position, dmg)`，但函数签名是 `spawn_hit_fx(pos: Vector2, dmg: int)`。Godot 传参按参数名匹配，这里会直接报参数不匹配。照抄时改成 `pos`。（这是我核对出来的，视频本身没提。）

## 6. 对《余烬交锋》的落地方案

### 6.1 我们现在已有的（读了代码确认）

演出都在 battle_stage.gd 的 play_event 里，结算在 battle_rules.gd，两者分离，规则结果不受演出影响 —— 这个结构要保住。

- 拼点碰撞（clash 事件）：双方前冲 0.16 秒 → 放射线火花（sparks = 1.0，自绘 18 条线 + 一条横向冲击波线）→ 抖动 impact = 0.65 → 等待 0.20 秒 → 结果文字 → 回位 0.19 秒。
- 命中（strike 事件）：前冲 0.15 秒 → impact = 1.0 + 受击者闪白 + 伤害数字 → 等 0.09 秒 → 击退 17 像素（0.13 秒）→ 回位 0.11 秒。
- 闪白：把角色颜色往过曝白（1.45, 1.39, 1.32）插值，衰减速度每秒 3.5（约 0.29 秒淡完）。
- 抖动：整张舞台按 sin/cos 高频正弦偏移，幅度 = impact × 5 像素，衰减每秒 3.5。
- 火花：自绘放射线，衰减每秒 2.0。
- 伤害数字：会向上飘（每秒 36 像素）并淡出。
- 音效：程序合成，22050 采样率，clash 是 980Hz 加 1.47 倍频加噪声，strike 是 120Hz 加下滑音，带包络，单个 AudioStreamPlayer 多声部 8 个，音量 -18dB。选中/拼点/命中/格挡/胜利/失败各一种。

### 6.2 三种场景分别怎么办

#### A. 拼点碰撞（两把武器撞在一起）

性质是「两股力量对冲」，不是单方面砍中。所以：

- 顿帧要短：0.03～0.05 秒。拼点是回合节奏的一部分，停太久会让玩家觉得卡。视频给的是 0.1 秒（单方面命中），对拼点建议砍到三分之一。
- 闪白不要给受击者（双方都没被砍中）。改成火花本身瞬间增亮 —— 现有 sparks 的线条粗细和透明度是跟 sparks 变量走的，给它一个短促的过冲值即可。
- 抖动可以更小：现在的 impact = 0.65 保留，或略降到 0.5。
- 音效：拼点用「金属相击」感，比命中更亮更短，低频层可以更薄。目前 synth_audio 里的 clash 已经是 980Hz 加噪声，方向是对的，可以再补一层高频的「叮」。
- 加一个横向冲击波：现在那条横线是静态的一帧，可以改成以碰撞点为中心快速扩张变淡。

#### B. 拼点胜负（结果揭晓那一击）

这是全场最该给足反馈的地方。

- 顿帧给满：0.08～0.1 秒，这是视频作者说的「力量落地」那一下。
- 闪白 + 击退 + 形变：败方闪白、先压扁再弹回、击退距离拉开（现在的 17 像素对拼点胜负来说可以更大，比如 30～40 像素，并且带一点上抛或下沉）。
- 音效：三层全开，低频最重。
- 粒子：胜方或碰撞点放一次真粒子（现在只有自绘放射线）。
- 破币：如果胜负会破币，粒子应该从角色身上炸出来（角色位置），而不是从碰撞点。

#### C. 后续连击（一轮里多次 strike）

- 顿帧要递减：连击越往后，单次顿帧越短，或者只有第一击和最后一击给满，中间给短的。否则整个连击会拖成慢动作。
- 闪白和击退每段都给，但形变挤压的幅度可以逐段加大（压得越扁越狠）。
- 数字：现在数字位置用连击序号错开，方向是对的。建议再加一个「连击数」大字（x3、x4），每次命中时缩放弹一下。
- 最后一击（连击段数 = 总段数）额外给一层：更强的闪白、更长的击退、更重的低频。
- 音高随机化：现有合成音是固定频率，连击多段听起来会像复读机。给每次播放加 ±10% 的音高随机就能解决。

### 6.3 优先级

先做（纯代码，不用素材）：

1. 顿帧。改动小、收益最大。
2. 形变挤压（scale 动画）。
3. 三层打击音（用现有 AudioStreamWAV 合成能力做三个音同时播 + 音高随机）。
4. 数字上浮 + 连击计数大字。
5. 震屏改成 trauma² 随机方向（现在是固定频率正弦，看起来像抖而不是摇）。

需要素材或动画才能做（先别排期）：

- 挥击动作本身（现在角色是整体位移，没有挥刀）。
- 受击方向的倾倒 / 被打飞。
- 刀光、拖尾。
- 真粒子特效与冲击波环（GPUParticles2D 预设需要美术配合调参）。
- 角色换成有细节的精灵图（现在角色是代码画的色块，闪白和挤压在这类色块上效果有限）。

### 6.4 两个必须注意的坑

1. 顿帧会和演出序列打架，但结果是对的。我们的演出序列是用 `get_tree().create_timer(...)` 一段段 await 等下去的，这些 timer 默认受 time_scale 影响，所以顿帧期间整个演出会被冻住，恢复后继续 —— 这正是想要的效果。危险在于恢复用的那个 timer 必须是忽略 time_scale 的那个，否则永远恢复不了。另一个细节：我们的演出有加速参数（duration = 1.0 / speed），加速时再叠一个全局 time_scale 会互相影响，建议加速只作用在演出层的等待时长上，不要去改全局 time_scale。
2. 所有打击感的东西都必须留在演出层，不能进 battle_rules.gd。README 里写明「战斗结算与动画播放分开，加速演出不改变规则结果」，顿帧、震屏、闪白、音效全部属于演出层，改动不能影响随机种子和事件记录。

## 7. 可直接粘进 AI 的完整文本块

下面这段可以整段复制给一个聊天 AI，让它按同样标准继续做打击感方案。里面不含本地路径和行号。

```
你是一位熟悉 Godot 4 和游戏手感调校的开发者。我会把一份视频学习笔记发给你，里面包含一个「打击感六层」的拆解方法。我需要你基于它，为我的回合制卡牌拼点游戏《余烬交锋》写一份可执行的打击感实施方案。

【方法论：打击感六层】
一个打击瞬间由六件小事同时发生组成，缺一件就会「散」。
01 顿帧：命中瞬间把 Engine.time_scale 设成 0，停 0.05 到 0.1 秒再恢复。关键坑：恢复用的定时器必须忽略 time_scale，否则死锁。
02 震屏：给舞台一个 trauma 值，命中时加 trauma，每帧按平方衰减，偏移取随机方向。轻击微颤，重击猛震。
03 受击闪白：canvas_item 着色器里用 flash 参数把颜色往白色混，命中时从 1 快速 tween 回 0，约 0.12 秒。每个受击者要有独立材质实例。
04 击退加形变：命中时给受击者一个方向速度，同时把 scale 压扁（例如 1.4 比 0.6），再用弹性缓动弹回原尺寸。力量必须有去处。
05 粒子加跳字：命中时实例化一个 one_shot 的 GPUParticles2D 当火花，再在受击点上方生成伤害数字。
06 分层音效：低频重击、中频碎裂、高频风声三个音源同时播，每次播放把音高随机上下 10%，避免机械重复。
作者原话：6 层效果等于 6 行调用，每一层都很小，叠起来就是质变。

【我的游戏现状】
引擎 Godot 4，2D，战斗与结算分离：规则层算结果并产出事件列表，演出层按事件播放动画，演出加速不改变规则结果。

已有反馈的衰减：闪白和抖动都是每秒衰减 3.5，火花每秒衰减 2.0。
缺少：顿帧、形变挤压、分层音效、真粒子、冲击波扩散环、连击计数。

【游戏的三种打击场景】
A 拼点碰撞：双方武器对撞，是两股力量对冲，不是单方面砍中。节奏要快，不能拖。
B 拼点胜负：结果揭晓的那一击，是全场最该给足反馈的地方。
C 后续连击：一轮里连续多次命中，需要分层递减，避免整段变成慢动作。

【我要你输出的东西】
1. 按上面三种场景分别给方案：每层（顿帧、震屏、闪白、形变、击退、粒子、数字、音效）写清楚参数建议和理由。
2. 给一份可以直接写进 Godot 4 的 GDScript 代码骨架，函数命名用清晰的中文注释说明每一步在做什么，演出层单独成一个模块，不要改到规则层。
3. 特别处理两个问题：一是顿帧与演出层的 await 序列如何配合才不会死锁、加速演出时如何避免和全局 time_scale 互相干扰；二是连击时顿帧和强度如何递减。
4. 指出哪些效果因为角色是色块而不是精灵图而效果有限，并说明换成精灵图后需要补什么。
5. 不要泛泛而谈，给具体数值（秒数、像素、倍率），并说明这些数值是怎么推出来的。
```

## 9. 待确认事项

- 打击感的强度分级（轻击 / 重击 / 破币 / 必杀）要不要做四档，还是先只做两档。这会决定参数是写死还是查表。
- 拼点碰撞要不要也走完整六层，还是只给三层的简化版。
- 顿帧是否影响整个游戏（推荐）还是只影响战斗演出层（需要额外设置 process_mode）。
- 加速演出（speed 参数）打开时，顿帧是按比例缩短还是保持绝对时长。
- 角色什么时候从色块换成精灵图 —— 这决定了形变和闪白能做到什么程度，是本次方案排期的前置条件。
- 是否要把这套六层方法写成项目内的统一规范（类似文档里的其他规范），让后续所有战斗演出都照它走。
