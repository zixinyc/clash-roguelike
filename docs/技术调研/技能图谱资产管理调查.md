## 2026-11-01：现成方案补充比较

用户已确认：技能资料库＋节点拼效果；先专用于《余烬交锋》；编辑后可选择使用者、目标直接测试。当前仍在选型与设计阶段，不代表批准安装框架或改造战斗系统。

此前只提 Unity 通用图谱与 Godot 技能运行库，覆盖不足。现补查官方 README：

| 项目 | 已在文档确认 | 适配判断（尚未实机验证） |
| --- | --- | --- |
| https://github.com/gamesmiths-guild/forge-godot | Statescript 技能图谱、属性/效果/技能资源、可玩示例，含回合制与图谱示例；Godot 4.7+ .NET、.NET 8+；API 尚在发展 | 最接近完整需求，优先考察；当前标准版 Godot + GDScript 工程引入它有环境与战斗桥接成本，不能称开箱接入 |
| https://github.com/cratercrash/godot-orchestrator | 通用可视化编程、图编辑；兼容表标 Godot 4.7 配 v2.5 分支 | 可复用图编程能力，仍须封装拼点/破币/cost 等领域节点和技能资料库 |
| https://github.com/don-tnowe/godot-resources-as-sheets-plugin | 文件夹中的 Resource 以表格浏览编辑，Godot 4 分支 | 适合技能库批量修改，不提供技能效果图谱执行 |
| https://github.com/LiGameAcademy/godot_ability_system | README 描述资源配置、行为树技能逻辑、状态与效果链，有中文文档 | 可作另一技能框架候选；不能仅凭自述认定成熟度或图谱交互满足需求 |

结论：确有可复用项目，不应先默认从零定制。现成框架文档核对不等于验收。下一步选型验证应围绕实际“编辑→保存→重载→执行→观察结果”，验证与原有 cost、拼点顺序和规则确定性的衔接后，再确定复用和定制边界。

定制并非简单画面：需要定义触发与目标、执行顺序、合法连线、保存兼容、撤销、错误提示及实战一致的测试入口。应先比较复用成本，避免既重写图编辑器又迁移整套战斗框架。
