# 杀戮尖塔开源卡牌设计与美术调研

调研日期：2026-11-20
调研范围：GitHub 上与《Slay the Spire》相关的开源实现，重点看「卡牌设计代码」和「美术资源」两块。
调研目的：为《余烬交锋》（Godot 4.7.2）提供可借鉴的卡牌数据结构和卡牌交互方案。

---

## 一、一句话结论

（卡牌设计代码有很多成熟可借鉴的开源实现，美术那边基本没有干净授权的杀戮尖塔卡面。）

- 卡牌数据结构：推荐抄 `dataEcto/godot-slay-the-spire-clone` 的 Godot Resource 方案，和《余烬交锋》同为 Godot，能直接对上。
- 卡牌交互（拖拽、瞄准目标、状态机）：推荐抄 `WaffleAWT/Godot-4.2-Card-Game-Starter-Template`（MIT，Godot 4）。
- 卡牌效果的数据驱动写法：推荐看 `Chrisl252/spiresofazeroth` 的 JSON + op 指令表，是这批里工程化最成熟的。
- 美术：所有找到的杀戮尖塔同款卡面要么是暴雪/暴雪风素材，要么是 Mega Crit 原画，都是别人的版权。能放心用的只有像素小人图和卡背这类通用素材。卡面建议自己画或用 AI 生成。

## 二、卡牌设计代码（按可借鉴价值排序）

### 1. dataEcto/godot-slay-the-spire-clone（首选，Godot）

- 地址：https://github.com/dataEcto/godot-slay-the-spire-clone
- 语言：GDScript（Godot），145 个文件，52 张图
- 授权：仓库没有 LICENSE 文件（等于默认保留所有权利）。代码思路可以读，代码本身别直接抄进项目。
- 为什么推荐：卡牌就是 Godot 的 Resource，和《余烬交锋》技术栈完全一致。

核心数据结构 `custom resources/card.gd`：

```gdscript
class_name Card
extends Resource

#Enum's based on Slay The Spire
enum Type {ATTACK, SKILL, POWER}
enum Target {SELF, SINGLE_ENEMY, ALL_ENEMIES, EVERYONE}

@export_group("Card Attributes")
@export var id: String
@export var type: Type
@export var target: Target

func is_single_targeted() -> bool:
	return target == Target.SINGLE_ENEMY
```

每张牌是一个 `.tres` 资源文件，新建牌 = 复制一个文件改数字，策划也能改：

```
characters/warrior/cards/warrior_axe_attack.tres
  script = ExtResource("1_nere8")   # 指向 custom resources/card.gd
  id = "warrior_axe_attack"
  type = 0                          # 0=攻击 1=技能 2=能力
  target = 1                        # 0=自己 1=单体敌人 2=全体敌人 3=所有人
```

配套脚本：
- `scripts/card_ui.gd`：卡牌界面，负责把输入转发给状态机
- `scripts/hand.gd`：手牌容器，负责把卡牌塞回手牌
- `scripts/card_states/`：卡牌状态机（基础/点击/拖拽/瞄准/释放）

值得注意：这套的状态机是「界面层」的状态机，卡牌逻辑本身没有分开，适合只借鉴界面手感。

### 2. WaffleAWT/Godot-4.2-Card-Game-Starter-Template（卡牌交互首选，MIT）

- 地址：https://github.com/WaffleAWT/Godot-4.2-Card-Game-Starter-Template
- 语言：GDScript（Godot 4.2），20 个文件，只有模板骨架
- 授权：MIT，可自由使用、修改、商用（保留版权声明即可）
- 为什么推荐：授权干净 + 纯 Godot + 正好是卡牌拖拽这套交互

五个状态，枚举就是卡牌交互的全部：

```gdscript
class_name CardState
extends Node

enum State {BASE, CLICKED, DRAGGING, AIMING, RELEASED}
signal transition_requested(from: CardState, to: State)
```

状态机本体 `Scripts/card_state_machine.gd`：

```gdscript
class_name CardStateMachine
extends Node

@export var initial_state : CardState
var current_state : CardState
var states := {}

func init(card : CardUI):
	for child in get_children():
		if child is CardState:
			states[child.state] = child
			child.transition_requested.connect(_on_transition_requested)
			child.card_ui = card
	if initial_state:
		initial_state.enter()
		current_state = initial_state
```

场景里状态节点直接挂在卡牌节点下（`Scenes/card_ui.tscn`）：

```
CardUI (Control)
├── Color (ColorRect)          # 卡面底色
├── State (Label)              # 状态文字
├── DropPointDetector (Area2D) # 落点检测
└── CardStateMachine (Node)
    ├── CardBaseState
    ├── CardClickedState   state = 1
    ├── CardDraggingState  state = 2
    └── CardReleasedState  state = 4
```

关键点：落点检测用 Area2D 的 area_entered / area_exited，卡牌自己维护一份可落点列表，选目标时直接读这个列表。这套《余烬交锋》可以直接用。

### 3. Chrisl252/spiresofazeroth（卡牌数据工程化最好，MIT）

- 地址：https://github.com/Chrisl252/spiresofazeroth
- 语言：JavaScript，640 个文件，138 张图，67 star
- 授权：MIT（代码）。README 明确写了：暴雪的美术、模型、音效不打包，运行时从 thewowdb.com 下载缓存。所以仓库里没有卡面。
- 为什么值得看：卡牌写成「一份 JSON + 一张指令表」，加新牌不用改代码。

卡牌数据结构（`data/classes/warrior.json` 的 cards 数组）：

```json
{
  "id": "heroic-strike",
  "name": "Heroic Strike",
  "icon": "ability_rogue_ambush",
  "type": "attack",
  "rarity": "basic",
  "cost": 1,
  "target": "enemy",
  "flags": [],
  "text": "Deal 8 damage. Gain 5 Rage.",
  "effects": [
    {"op": "damage", "amount": 8},
    {"op": "gain_resource", "resource": "rage", "amount": 5}
  ]
}
```

升级版直接嵌在同一张牌里（`upgrade` 字段）：

```json
"upgrade": {
  "name": "Goblin Sapper Charge+",
  "cost": 1,
  "text": "Deal 15 Fire damage to all enemies. Take 5 damage. Exhaust.",
  "effects": [
    {"op": "damage", "amount": 15, "target": "all_enemies", "school": "fire"},
    {"op": "damage", "amount": 5, "target": "self"}
  ]
}
```

效果指令（op）表实际用到的：
damage / block / heal / apply（加状态：vulnerable、weak、stun、strength、dexterity、ritual…）/ remove / draw / gain_energy / energy_next_turn / gain_resource / conditional（概率分支）/ taunt / cast_interrupt / retreat / double_damage_next

文件分工：
- `data/classes/*.json` 各职业的牌、遗物、起始卡组
- `data/neutral-cards.json` 中立牌
- `data/status-cards.json` 状态牌
- `data/relics.json`、`data/potions.json`、`data/keywords.json`、`data/index.json`
- `js/engine/effects.js` 指令实现
- `js/engine/deck.js`、`js/engine/cardtext.js` 牌组与文本渲染

这套「一张牌 = 一串 op」的思路，对《余烬交锋》后面加符文（阶段 3 的五枚符文）特别有用：符文可以直接复用 op 表。

### 4. jahabrewer/decapitate-the-spire（纯逻辑参考）

- 地址：https://github.com/jahabrewer/decapitate-the-spire
- 语言：Python，24 个文件，无界面
- 授权：GPL-3.0（传染性协议，想抄代码进项目就别用，只做逻辑参考）
- 价值：把战斗规则写成纯函数，适合拿来对照检查规则有没有漏。

### 5. NightCodeOfficial/sts2-data（原始卡牌文本数据集）

- 地址：https://github.com/NightCodeOfficial/sts2-data
- 内容：cards/ironclad.json、silent.json、defect.json、regent.json、necrobinder.json、colorless.json
- 授权：没有 LICENSE 文件。文本内容本身来自游戏，属于游戏内容不是开源代码。
- 字段很薄：

```json
{"card_name":"Bash","class":"basic","character":"ironclad",
 "card_type":"attack","effect":"Deal 8 damage. Apply 2 Vulnerable."}
```

- 用途：当「设计参照表」查数值平衡很方便，但别直接搬文字进自己项目。

### 6. ycarowr/UiCard（Unity，MIT，577 star）

- 地址：https://github.com/ycarowr/UiCard
- 语言：C#（Unity），358 个文件，163 个脚本
- 授权：MIT
- 价值：卡牌交互的最完整参考实现——抽牌动画、悬停、拖拽、弃牌堆、手牌自动排序、卡牌弯曲。
- 但它是 Unity 的，搬到 Godot 要重写。美术方面只有 `Cardback.gif` 一个卡背 + 几张演示图，卡框是代码拼的。

## 三、美术资源现状（这部分要说实话）

逐个仓库核对下来，美术情况是这样：

| 仓库 | 美术内容 | 能不能用 |
|---|---|---|
| dataEcto/godot-slay-the-spire-clone | 51 张像素小人图 tile_XXXX.png（12x12 到 32x32 的角色）+ heart/arrow/background | 仓库无授权声明，且是战场角色不是卡面 |
| hanmi255/SlayTheSpire | 同样是 51 张像素小人图 + 音频 + 字体 + 着色器 | MIT，但只有 1 个代码文件，本质是素材包 |
| bhsaio145/SlayTheSpire-Clone | 3 张战斗背景/角色精灵 + 5 张技能图标 + 1 个瞄准框 + 字体 + 音效 | 仓库无 LICENSE |
| Chrisl252/spiresofazeroth | 只有 UI 边框/按钮/职业头像等通用 UI，暴雪素材运行时外部下载 | 代码 MIT，卡面没有 |
| ycarowr/UiCard | Cardback.gif 一个卡背 + 5 张演示图 | MIT，但基本没有原创卡面 |
| spire-codex | 反编译杀戮尖塔 2 的完整资源（1.36 GB） | 授权是「Other / 无声明」，是反编译产物，别碰 |

结论：

1. 找不到任何「可自由商用的杀戮尖塔风格卡面」。
2. 网上能看到的 StS 卡面几乎都是 Mega Crit 的原画，或者从游戏里扒出来的（spire-codex、ModTheSpire 生态这类），直接用会有版权问题。
3. 真正干净的替代路线有三条：
   - 自己画卡面（东方Project 风格，贴合《余烬交锋》主题）
   - 用 AI 生成卡面（项目里已经有 art-gen 工具链，见 `D:\游戏项目\art-gen`）
   - 用通用 CC0 素材拼卡框：Kenney 的 Board Game Icons、Playing Cards Pack 都是 CC0，游戏图标站 game-icons.net 是 CC-BY，都能商用
4. 像素小人图那套（dataEcto / hanmi255）倒是能当参考，如果《余烬交锋》要做像素风战场角色。

## 四、给《余烬交锋》的落地建议

结合上面的调研，建议这样落地：

1. 卡牌数据：抄 `dataEcto` 的 Resource 方案（牌 = 一个 .tres 文件 + 一个 Card 脚本），但要按《余烬交锋》现有约定扩字段（点数、速度、绝缘、独行这些）。
2. 卡牌交互：抄 `WaffleAWT` 的五状态机（BASE / CLICKED / DRAGGING / AIMING / RELEASED）+ Area2D 落点检测。MIT 授权，可以放心用，署名保留即可。
3. 卡牌效果：抄 `spiresofazeroth` 的「一串 op」写法。好处是加符文、加新效果不用改引擎代码，阶段 3 的五枚符文可以直接挂新的 op。
4. 升级卡：参考 `spiresofazeroth` 的 `upgrade` 内嵌字段，或者用两个 .tres 文件，避免同一张牌里塞两套数值。
5. 美术：卡面走自绘或 art-gen 生成；卡框用 CC0 素材拼；像素角色图可以在 dataEcto 那套基础上改。

## 五、复现方式

本地已克隆，统一放在素材目录下的「参考源码」里：

```
D:\游戏项目\asset\参考源码\
├── .gdignore          空文件，让 Godot 跳过这个目录，不做资源导入
├── dataecto-sts       13.6 MB  杀戮尖塔复刻（Godot）
├── hanmi-sts          13.5 MB  杀戮尖塔素材包（Godot，MIT）
├── bhsaio-sts         51.1 MB  杀戮尖塔复刻（Godot）
├── spiresofazeroth            卡牌数据工程化参考（MIT，仅文件树）
├── waffle-cardgame            卡牌状态机（MIT，仅文件树）
├── uicard                    Unity 卡牌 UI 框架（MIT，仅文件树）
├── decapitate                Python 战斗逻辑参考（GPL-3.0，仅文件树）
├── sts2-data                 卡牌文本数据集（无授权声明，仅文件树）
└── _预览                     调研时下载的样例贴图
```

`.gdignore` 是 Godot 自带的忽略标记，目录里有它，Godot 就不会去导入里面的图片，
所以这个文件夹不会被塞进 `battle-demo` 的资源缓存。如果以后要把 `asset/` 整个复制进
`battle-demo/`，记得连同 `参考源码/` 一起复制，`.gdignore` 会自动挡住导入。

需要重新拉取时：

```powershell
cd D:\游戏项目\asset\参考源码
git clone --depth 1 https://github.com/dataEcto/godot-slay-the-spire-clone.git dataecto-sts
git clone --depth 1 https://github.com/hanmi255/SlayTheSpire.git            hanmi-sts
git clone --depth 1 https://github.com/bhsaio145/SlayTheSpire-Clone.git     bhsaio-sts
git clone --depth 1 https://github.com/Chrisl252/spiresofazeroth.git        spiresofazeroth
git clone --depth 1 https://github.com/WaffleAWT/Godot-4.2-Card-Game-Starter-Template.git waffle-cardgame
git clone --depth 1 https://github.com/ycarowr/UiCard.git                   uicard
git clone --depth 1 https://github.com/jahabrewer/decapitate-the-spire.git  decapitate
git clone --depth 1 https://github.com/NightCodeOfficial/sts2-data.git      sts2-data
```
