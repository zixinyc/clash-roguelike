# 全新拼点与硬币系统 · 2026-11-17

当前实现在 Unity 单机版中。地图、角色生命、速度规则、费用、奖励和原战斗胜负条件保留。Godot 的 `battle-demo` 是参考版本，本轮没有修改其 GDScript 战斗。

## 本轮改变

每个攻击技能保存独立的初始点数、拼点硬币点数、攻击硬币点数、固有硬币数和效果列表。当前已有牌的两种加值先分别继承原加值，避免凭空重做平衡；它们是独立字段，测试以拼币 +2、攻币 +7 验证可分别设置。防御牌沿用零攻击硬币，仍执行原有护盾效果，不会凭空生成攻击。

1. 创建技能的运行时行动，余币初始化为固有硬币数。固有数据不随投掷修改。
2. 双方每轮重新投掷各自全部余币，点数为 `当前初始点数 + 本轮正面数 × 当前拼点硬币点数`。本轮结果不继承上轮。
3. 平局双方不损币，继续重投；只在点数不同时，败方减一枚。没有“三次平局随机判胜”。
4. 一方归零立即结束拼点，只有胜方进入攻击。攻击预算就是这一刻的余币，不重建/修复硬币。
5. 每次攻击重新投一枚，计算 `当前初始点数 +（正面 ? 当前攻击硬币点数 : 0）+ 该次原始伤害效果修正`，随后消耗一枚。每击从初始点数重算，不继承上一击伤害。
6. 原始伤害交给现有伤害适配层，再处理护盾、生命扣除和命中后角色效果。界面与日志区分原始伤害、护盾吸收和实际伤害。

源规则里我方 65%、敌方 50% 的正面率继续使用，未另加概率平衡改动。速度和投币共用原来的确定性 `BattleRandom`；动画、演出倍速和跳过不产生随机结果。

“余势追击”原效果会额外进行一次 4 点攻击，与新规则冲突，现已停用且卡面明确注明。该牌的基础点数、费用和固有硬币保留，没有擅自把旧效果换成别的加伤。准备、破阵、援护、观察、敌人被动等不与新规则冲突的行为保留；拼点专用加成不会带到攻击阶段。

## 数据与运行时

| 设计字段 | C# 数据入口 | 性质 |
| --- | --- | --- |
| `base_power` | `CoinSkill.BasePower` | 技能初始点数 |
| `clash_coin_power` | `CoinSkill.ClashCoinPower` | 拼点正面加值 |
| `attack_coin_power` | `CoinSkill.AttackCoinPower` | 攻击正面加值 |
| `coin_count` | `CoinSkill.CoinCount` | 固有数量，运行时不修改 |
| `effects` | `CoinSkill.Effects` | 只读效果定义副本 |
| `remaining_coins` | `CoinAction.RemainingCoins` | 只读；只由拼点失败/攻击消耗减少 |
| `clash_round` | `CoinAction.ClashRound` | 当前拼点轮次 |
| `clash_winner` | `CoinAction.ClashWinner` / `CoinClash.Winner` | -1 未决，0 左侧，1 右侧 |
| `attack_count` | `CoinAction.AttackCount` | 本次技能已执行的逐币攻击数 |

`PortContent.cs` 配置当前专属/通用牌；`BattleRules.cs` 保留旧单场牌定义，但也使用相同硬币核心。当前仍沿用项目既有的 C# 配牌方式，没有加入 JSON 热加载器。

新代码分工：

- `CoinCombat.cs`：不可变技能/效果定义、带期限状态、受限效果处理、行动运行时、逐轮拼点、逐币攻击。`CoinClash.Step()` 每次只处理一轮，`CoinAction.NextAttack()` 每次只处理一枚。
- `CoinLog.cs`：双方完整投掷结果、公式、破币、逐击原始伤害和累计值的日志。
- `PortBattleRules.cs` / `BattleRules.cs`：保留各自的速度队列、角色效果、资源和护盾，接收共同硬币核心的结果。
- `CoinBattleView.cs`：双方技能、初始/拼币属性、正反面动画、轮次、失去硬币、最终胜者、攻击余币与累计统计，以及可滚动战斗记录。

事件携带独立快照，渲染层不会投币或结算伤害。状态列表也深复制，回看快照不会让实际增益提前到期。

## 效果扩展能力与边界

效果用 `CoinEffect` 明确 ID、触发时机、目标属性、数值、作用范围、持续回合、叠加规则、条件和作用对象。目标属性只有 `BasePower`、`ClashCoinPower`、`AttackCoinPower`、`RawDamage`，没有硬币数、余币或攻击次数选项；非法枚举也会被拒绝。效果定义没有任意执行代码或直接拿到行动计数器的接口。

支持技能发动、拼点开始、每轮前、单轮胜/负/平、最终拼点结束、每击前、攻击正/反面、命中、技能结束这 12 个时机。条件支持无条件、最终拼点胜/负、正/反面和实际命中。

作用范围包括整次技能、当前拼点、当前拼点轮、当前一击、持续状态。前三种按相应阶段使用；当前轮/当前击的临时修正会在下一轮/下一击清空。状态指定持续回合，并在战斗回合交替时到期，不会偷偷修改地图回合。叠加可选累加、替换、刷新期限、已有则忽略。状态可作用于自身或对方。

示例仅用于说明配置，不会自动加入正式手牌：

```csharp
var skill = new CoinSkill("猎人的突刺", 5, 2, 3, 3, new[] {
    new CoinEffect("突刺正面强化", CoinTrigger.AttackHeads,
        CoinStat.RawDamage, 1, CoinEffectScope.Attack,
        condition: CoinCondition.Heads)
});
```

命中回调对一枚攻击硬币只允许调用一次。这里“命中”指对仍存活目标执行了一次打击，即使全部被盾吸收也属于命中；角色原有“造成生命伤害后”的条件仍独立保留。目标提前退场后，其余硬币仍完成原始判定并消耗，实际伤害为零，不再次触发命中，也不会转移到其他目标。这样攻击预算始终守恒。

目前通用效果处理实现了数值修正和带期限的属性增益/减益。中毒跳伤、眩晕、复杂条件脚本等具体新效果尚未配置，需要增加相应处理器；无需开放硬币计数器来实现它们。

## 持续平局

若未来把双方配置成“同初始、拼点加值为零”等永远无法分胜负的技能，严格按本次规则就会永远平局。本实现不会偷偷损币、恢复硬币、宣布平手或随机判胜。

游戏界面使用逐事件的 `ResolveStream` / `EndTurnStream`，每轮让出画面更新，持续平局时仍能操作倍速、快速演出或重开。快速演出也不会强行改变胜负。供测试用的同步 `Resolve()` / `EndTurn()` 会一直计算到结束；对自定义永不决胜配置应使用流式接口，避免在单线程工具中等待其同步返回。是否为此类技能另定规则，需后续讨论。

| 要求的情况 | 验证 |
| --- | --- |
| 不同点数时败方失一币 | 固定投掷与每轮种子检查 |
| 平局不损币并重投 | 固定平局、连续 512 轮平局、实际画面 |
| 连续失败归零立即结束 | 固定两轮失败，结束后再步进不产生随机数 |

| 每击只投一枚 | 严格投掷队列及数量检查 |
| 每击重新计算 | 初始 5、攻币 +7、反/正/反得到 5、12、5 |
| 两种硬币加值独立 | 拼币 +2 / 攻币 +7，分别进入公式 |
| 效果不能改硬币数 | 受限属性、非法目标拒绝、无公开计数器 setter、全时机数量守恒 |
| 已耗硬币不能再用 | 结束后无投掷、无攻击；同一运行时不能再次拼点 |
